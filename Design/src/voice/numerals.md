# src/voice/numerals.js — 数字的「念法」（报数 / 读秒用）

> 层：语音（文本） ｜ 99 行 ｜ 纯函数，**不 import 任何东西**
> 一句话：把 `5` 变成「五」/「five」，再交给 TTS —— 别让音色去猜阿拉伯数字怎么念。

## 1. 它解决什么问题（为什么需要它）

私教式报数要「一、二、三…五个了」这种节奏感。直接把数字塞进模板交给 TTS，会出现
「五 / 伍 / five」三种读法（取决于音色与语言），节奏就散了。所以先换成该语言的数词。

## 2. 关键数据结构 / 常量（表）

| 名称 | 位置 | 内容 | 说明 |
|---|---|---|---|
| `ZH_DIGITS` | L23-L26 | 零 一 二 三 四 五 六 七 八 九（`\u` 转义） | 避免源码出现中文字面量（`test-i18n` 会扫） |
| `ZH_TEN` / `ZH_HUNDRED` | L28 / L29 | 十 / 百 | 位值 |
| `zhNumber(value)` | L36 | 1~999 → 中文数词 | 0 → 「零」；超范围回阿拉伯数字 |
| `enNumber(value)` | L71 | 1~999 → 英文数词 | `one / twenty-one / one hundred five` |
| `numberWord(value, lang)` | L95 | 按语言分派 | `lang='zh'` → `zhNumber`，否则 `enNumber` |

## 3. 算法与流程（步骤化）

```
zhNumber(v):
  v = 取整；不在 0~999 → String(v)（绝不编造）
  拆 百位 / 十位 / 个位：
    百位 → 「X百」；十位 0 且个位非 0 且百位非 0 → 补「零」
    十位 1 且百位 0 → 「十」（不说「一十」）
  → 拼字符串
enNumber(v):
  拆 百位 / 十位 / 个位：hundred → "one hundred"，十位 20~99 → tens + "-" + digit
  → 拼字符串（1~19 用固定表）
```

（具体实现见 L36-L94；规则就是「中文省略一十、英文加连字符」这两条惯例。）

## 4. 对外接口

| 导出 | 位置 | 签名 | 返回 |
|---|---|---|---|
| `zhNumber(value)` | L36 | 数 | 中文数词（1~999） |
| `enNumber(value)` | L71 | 数 | 英文数词（1~999） |
| `numberWord(value, lang='zh')` | L95 | 数 + 语言 | 该语言的数词；非法值回字符串 |

## 5. 与其它文件的关系

- 上游：无（刻意零依赖，避免与 `i18n.js` 循环）。
- 下游：`voice/rules.js`（`numberWord` 用于「每 5 个报一次」「五个了」这类模板）。

## 6. 易错点与设计取舍

- **只做 1~999**：报数 / 读秒永远在这个范围；更大的数直接回阿拉伯数字（比编错好）。
- 中文用 `\u` 转义：`tests/test-i18n.mjs` 要求 `src/` 下不出现写死的中文，连数词也不例外。
- 不做「第一 / 第二」序数：序数在 `voice/parse.js`（识别）与 locales（显示）里各自处理。
- `numberWord` 对未知语言**回退英文**（不是中文），与 `i18n.js` 的兜底语言一致。
- 不要在模板里直接拼阿拉伯数字再指望 TTS —— 这正是本文件存在的理由。
