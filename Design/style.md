# style.css — 全部样式（深色主题 + 圆环体系 + 弹窗 + 手机适配）

> 层：界面（表现） ｜ 3282 行 ｜ 无预处理器、无框架
> 一句话：一个文件管全部视觉；**尺寸/颜色令牌集中在 `:root`**，改一个数整站跟着变。

## 1. 它解决什么问题（为什么需要它）

项目零依赖，不引 Tailwind / CSS-in-JS。所有视觉规则（深色玻璃卡、圆环、HUD、弹幕、
弹窗、手势菜单、手机排布）都在这一个文件里。为了避免「同一个圆环在两个地方写两套尺寸」，
关键数值全部提成 CSS 自定义属性，JS 侧也有同名常量兜底（见 `app.js` 的 `RING_PX_FALLBACK`）。

## 4. 对外接口

- **类名契约**：`app.js` 动态插入的每个节点（`.danmaku` / `.ring` / `.criteria-bar` / `.hud-*` …）
  都依赖这里的类名；改名要两边一起改。
- **CSS 变量契约**：JS 侧读不到元素尺寸时按同名常量兜底（`RING_PX_FALLBACK` 与 `--ring-px`
  的 clamp 参数一致）。
- **状态类**：`.is-hidden` / `.hidden` / `[hidden]` / `.active` 等由 `app.js` 切换。

## 5. 与其它文件的关系

- 下游：`index.html`（结构）、`src/app.js`（动态类名 / 圆环布局计算）、`src/voice/danmaku.js`

## 6. 易错点与设计取舍

- **圆环尺寸只有 `--ring-px` 一个来源**：历史上左下退出环在元素还隐藏时量尺寸（`clientWidth = 0`），
  于是永远比右上角小 —— 修法就是统一变量 + JS 兜底同一组 clamp 参数（L27-L38 的注释）。
- **`--danmaku-*` 必须与 `danmaku.js` 的常量同值**：两边都写死，测试会对照。
- 镜像时视频与画布都被 `scaleX(-1)` 翻过来，画布上的文字要再翻一次（`render.js` 的 `mirror`）——
  CSS 不能替它解决。
- 手机排布靠 `clamp()` + 竖屏遮罩，不写媒体查询瀑布：新增元素要同时检查窄屏。
- 触摸目标 ≥ 44px（L3230 起）：这是可用性底线，不要在窄屏把它压小。
- 弹幕与 HUD 的层叠顺序不能反：弹幕只占上半屏，就是为了不压 HUD（见 `danmaku.js`）。
