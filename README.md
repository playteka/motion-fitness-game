# 体感健身游戏 · Motion Fitness Game

[中文](README.md) · [English](README.en.md)

用普通摄像头做动作识别的健身小游戏：**19 个动作**分成 **上肢 / 下肢 / 核心 / 全身 / 拉伸** 五大类，
主页按分类挑选动作，进去就能练；**计数类自动数次数、计时类自动计时**，
并且**按「动作要领」一步一步计分**——每达成一个要领就立刻加分、响铃、用语音念出要领。

界面支持 **中文 / English** 两种语言，点右上角的 **⚙️ 设置**随时切换（语言、识别模型、音效、背景音乐都在里面）。

纯前端实现，MediaPipe 姿态模型与 wasm 全部放在本地 `vendor/` 目录，**不联网、不上传画面**。

## 功能亮点

- **动作主页（五大分类）**：进站先看到分类动作墙 —— 上肢（2）· 下肢（5）· 核心（6）· 全身（4）· 拉伸（2），
  每个动作一张卡片（图标 + 名称 + 计数/计时 + 目标 + 判定依据），还有搜索框。点卡片进动作页，左上角的 🏠 图标随时回来。
  「开合跳」在全身分类里，「勾腿跳」在下肢分类里，两个都是**限时计数**：固定 60 秒，看你能做多少次。
- **主页只管挑动作（摄像头也会关掉）**：从动作页返回主页时**自动关闭摄像头**（指示灯灭、省电），
  再点任意动作会自动重新打开，不需要多点一次。
- **动作页 + 设置弹窗**：动作页右上角是 ⚙️ 设置，弹窗里集中放**语言、识别模型、音效、语音报数、背景音乐**，
  以及镜像、火柴人、角度、识别指标等开关 —— 不用再满屏找按钮。
- **运动前校准**：开始前画面里有一个**虚线人体剪影**（只勾勒外形，不用对齐骨骼），画面上方同步用文字提示
  「进入虚线轮廓内」；**只要识别到人体、并且全身都在画面里就放行**（约 0.6 秒），
  距离、左右、高度、机位、站定都只是建议（面板里用「·」标出），不再拦着开始。
  **识别成功（就位）的那一刻轮廓立刻隐藏**：它只负责「把你领进轮廓里」，倒计时、计数、暂停期间一帧都不画
  （见 [运动前校准](#运动前校准)）。
- **按动作要领逐步计分**：每个动作拆成 4~5 个可判定的步骤，做对一步立刻加分、响铃、打勾；
  整轮要领全部完成有满分奖励；计时类动作**每保持 1 秒 +1 分**。
- **关键帧就是唯一判据**：每个动作在进度条上拆成 4~5 个关键帧，**做到一格就点亮一格、加一格的分**；
  **全部关键帧都做到 = 计一次**。没有严格模式，也不再有单独的「计次判据」——判据与分数都挂在关键帧上
  （`tests/test-specs.mjs` 逐动作核对「链走完」与「计次」的同帧关系）。
- **限时计数（开合跳、勾腿跳）**：**固定 60 秒，看这段时间里能做多少次** —— 计次规则不变，只是「什么时候算完成」
  从「跳到目标次数」换成「时间到」；画面上显示 `⏱ 剩余 42 / 60 秒`，剩余 45/30/15/5 秒时会读出来，
  时间到立刻停表并把这一组写进记录（**52 次 / 60 秒**）。时长可以在主页右上角的 🎯 运动设定里选中这个动作后改（30~120 秒）。
  见 [限时计数](#限时计数开合跳--勾腿跳固定-60-秒看能做多少次)。
- **有效计数判定（只有宽松一档）**：**大体上做到了就算一次** —— 浅一点的自重深蹲/箭步蹲、只放一半多的俯卧撑、
  顶得不太高的臀桥都会计数，同时用语音把「蹲低一点 / 再放低一点 / 屁股再顶高一点 / 别塌腰」纠正出来，
  分数也会按质量打折。完全没做到位的（只是晃了一下）不会计数，也不会碎碎念。
- **每个动作都写着「判定依据」**：卡片与动作页会标明这个动作是靠什么判定的（肘关节屈伸 / 膝关节屈伸 /
  髋部抬起高度 / 双脚离地 / 身体姿势 …），摄像头判不准的动作会额外标注**粗略判定**。
- **实时状态反馈**：画面下方永远显示「现在是什么状态、卡在哪一步、还差多少度」。
- **🐞 识别指标面板（含「计数诊断」）**：除了原始数字（视角、可见度、各关节角度），第一行就是**计数诊断**——
  现在处在哪个阶段、这一轮的结算线（回到哪里才算一次）、本轮最小值/峰值、以及**上一次为什么没计上**
  （太浅 / 太快 / 幅度太小 …）。计数不对劲时把这一行念出来就能定位，不用猜。
  **左右交替类动作（勾腿跳 / 登山者 / 死虫式）也补上了诊断行**：两条腿当前的读数（在做的那一侧带 ✓）、
  交替线（进入 / 退出）、当前认的是哪一侧、以及距上一次计次的间隔 —— 「快节奏计不上」就是靠它定位的。
  勾腿跳还多一行**第二路证据**（膝角 +「脚跟到髋 ÷ 腿长」相对自己基线），「跳快了就计不上」的修复就建在它上面。
- **按当前语言的语音报数 + 音效**：要领达成有音阶上行提示音，第一次达成会念出要领。
  **语音一律不报分数**（用户要求：只报次数和读秒）—— 跨过 50 分时改念一句**激励语**，
  分数只出现在屏幕上（HUD、结算面板、训练记录）。
- **以语音激励为主，指导适度**：**每做一个动作都报数**（不会被别的提示吞掉），每 3 次给一句**激励**
  （**24 句轮换**：加油 / 太棒了 / 优秀 / 干得漂亮 / 就是这个节奏 / 你太厉害了 / 真有毅力 / 越做越顺 …），
  达标时先念达成再补一句鼓励，**整轮关键帧全做到**时会额外夸一句（完美 / 这一轮满分，太漂亮了 …），
  **一组结束**时报「本组 N 次」+ 一句夸奖（练得很好，给自己鼓个掌 …，同样不报分数）；
  **节奏特别快的动作例外**（开合跳、勾腿跳 —— 「开合跳一轮只有 0.6 秒、勾腿跳一秒约两下」，每次都报数既听不清又拖节奏）：
  它们（`catalog.js` 里的 `speakEvery: 5`）**每 5 次才报一次数**，激励语也按同样节奏降到每 5 次一句，
  报数那一帧不会同时念激励（两句挤在一帧会互相顶掉）；
  姿势纠正保留但明显降频（同一句 15~30 秒不重复，做过几次之后进一步放慢），「下一步做什么」也放慢到 9 秒一句
  —— 话语权留给报数与鼓励，基本不用盯着屏幕。
- **🎶 四首背景音乐可选（只在动作页播放）**：全部现场合成（不占空间也不需要联网），设置里「🎵 背景音乐曲目」随便挑 ——
  **回到主页会自动停掉背景音乐**（主页只是挑动作，不需要音乐），再进动作页自动接着放，你的选择会被记住。
  **城市跑动**（132 BPM，轻快摇摆）/ **霓虹脉冲**（144 BPM，四踩电子感）/ **晨光放克**（122 BPM，放克切分）/ **动力驱动**（152 BPM，摇滚推进）；
  鼓组是真合成的（底鼓、军鼓、踩镲、拍手），节奏感比原来强得多；念要领时会自动把音乐压低，不抢语音。
- **🦴 火柴人开关**：可隐藏骨架只留摄像头画面；**角度标注**可独立开关 ——
  打开后画面上会标出**这个动作真正被判的那个角度**（深蹲标膝/髋、俯卧撑标肘、**仰卧抬腿标「髋」**（腰腿夹角）+ 膝角），
  一边做一边能看到「离判决线还有多远」；判据不是关节角的动作（开合跳、波比跳、跳跃类）不标，免得画面全是数字。
  **骨架的颜色就是「现在行不行」的信号**（`app.js` 每帧给一个 status，`render.js` 的 `COLORS` 上色）：
  - **青绿色**（`ok`，默认）：识别到人、并且正在正常判定（姿势门控过了），最近 2 秒也没有纠正提示 —— 照着现在这样做；
  - **琥珀色**（`warn`）：两种情况 —— ① **还没进入这个动作要求的姿势**（`det.active === false`，判定暂停中，画面下方会写着缺什么，
    例如「请先躺下」）；② **最近 2 秒内刚念过一条纠正**（`now - state.lastCueAt < 2000`）—— 已经改对了也会再黄 2 秒，
    提醒你「刚才说的就是这里」，过了这 2 秒自己变回青绿；
  - **灰色**（`idle`）：这一帧**没有被当成有效的人**（`frame.ok === false`，判据见 `src/metrics.js` 顶部那三个常量）：
    12 个核心关节（肩 / 肘 / 腕 / 髋 / 膝 / 踝）的**平均可见度 ≤ 0.10**，或者判定用的 15 个点里**有三个以上看不见**
    （可见度 ≤ 0.02），或者**躯干长 ≤ 画面高的 2%**（关键点全塌成一点，跟踪快要丢的那种退化帧）。
    常见原因是人出画、离镜头太远、太暗 / 背光、身体大面积互相遮挡。灰色**不是报错**，回到画面里立刻恢复；
    完全找不到人时骨架会**整个消失**（而不是变灰），同时下方状态条会念「没找到人」。
    > 这几个门槛按用户反馈**放宽过**（原来是「平均 ≤ 0.16 或任意一点 ≤ 0.03」）：
    > 现在**双手举出画面、脚出画、脸和手指被挡住**都还照样算「识别到人」（脸和手指本来就不参与判定），
    > 整体偏暗时也能撑到平均可见度 0.10；同时补了一条「躯干长不能趋近 0」，把跟踪丢失瞬间的退化帧挡在外面。
  - 另外：校准阶段那条**虚线人体剪影**是独立的一套三色（亮天蓝 = 还没找到人、亮琥珀 = 正在调整、亮绿 = 已就位但还没保持够 0.6 秒），和骨架三色不是同一组。
    **亮绿之后约 0.6 秒轮廓就整条消失**（识别成功），所以训练中不会看到它。
- **画面上也显示「躯干 xx°」（躯干倾角）**：用户要求「要在画面上显示躯干倾角的度数，类似『髋』『膝』的度数显示方法」——
  凡是画面上已经标了关节角的 **16 个动作**（站立 / 俯撑 / 仰卧 / 跪撑那些判据是角度的动作），都会多一个**躯干倾角**标签，
  和「髋」「膝」**同一个画法**（深色胶囊 + 度数，跟着镜像一起翻，关掉角度开关就一起消失）；
  它标在**躯干中段并垂直于躯干方向让开一段**（站立时在躯干侧面、躺姿时在身体上方），不会和其它标签压在一起。
  > **坐姿体前屈补上了（用户反馈「没有显示角度」）**：它以前是「判据不是关节角就不标」的那一类，一个数字都没有 ——
  > 可它判的恰恰就是**前折幅度**（现在的要求是「躯干倾角 ≥ 28°」**且**「躯干角 + 髋角 ≈ 90°」，全是角度）。
  > 现在它标 **「髋 xx°」**（躯干与腿的夹角：坐直 ≈90°、折到 30° 时 ≈60°）和 **「躯干 xx°」**（判决线就是 28°），
  > 折多深一眼就能对着看，两个数加起来就是判据里的那个「≈90°」。
  > **站立体前屈**（判据是躯干倾角 ≥55° + 髋离地 ≤0.65）暂时仍旧不标数字，需要的话照这个改一行即可。
- **两条腿都在画面里时，左右膝分开标**（用户要求「当两条腿都在画面的时候，应该分别显示左膝和右膝的度数」）：
  这时画面上是 **「左膝 xx°」** 和 **「右膝 xx°」** 两个标签，各读各那一侧的角度（箭步蹲「两条腿都要弯」这种判据，一眼就能看出是哪条腿差）；
  只有一条腿看得清（侧拍时远侧腿被躯干挡住）时退回一个中性的 **「膝 xx°」**，不硬说左右。
- **平板支撑还会标「肩 xx°」和「肘 xx°」**（用户反馈「没有计时、主要是判断关节角度」）：
  「肩」是**肩关节角（髋-肩-肘）**，也正是现在决定计时跑不跑的那个角（小臂撑 ≈78°、趴着休息 ≈10°）；
  「肘」用来看你是小臂撑（≈90°）还是直臂撑（≈175°）。加上「髋」和「躯干」，用户说的四个数都在屏幕上。
  「两条腿都在画面里」用的是识别器自己那条 `frame.legsVisible`（两侧「髋-膝-踝」可见度都 > 0.16），和 🐞 面板里的「双腿可见」同一个条件；
  两个标签万一几乎重在一起（侧拍站姿），会有一个自动往上抬一行，不会叠成一团。
- **开合跳画面上显示「开合 0.83」**：它的判据不是关节角，而是**双腿开合幅度**（膝 / 踝取较大值，单位是躯干长），
  所以画面上标的也是这个幅度 —— 同款胶囊、同样跟着镜像翻转，就在两腿中间。用户问「开合跳怎么没有角度」，
  答案就是它本来就不靠角度判（其他动作才有「膝 132°」这种角度标签）。对照值：**≥0.66 计次、≤0.54 收回**。
- **目标进度环 + 两个记录图标 🏆 / 📜**：**最佳成绩**（每个动作最好的一次）和**运动记录**（最近 12 组）
  都在**顶栏图标打开的弹窗**里看，不再占用动作页的地方（用户要求）；数据存在浏览器本地。
- **离线可用**：模型与 wasm 都在本地，断网也能跑；画面不上传。

## 安装

### 第 0 步：拿到代码

**方式 A：下载 ZIP（推荐给不想折腾 git 的人）**

1. 打开 <https://github.com/playteka/motion-fitness-game>
2. 点绿色的 **Code** 按钮 → **Download ZIP**
3. 解压到任意目录，例如 `C:\Users\你的用户名\motion-fitness-game`（Windows）或 `~/motion-fitness-game`（macOS / Linux）

**方式 B：用 git 克隆**

```bash
git clone https://github.com/playteka/motion-fitness-game.git
cd motion-fitness-game
```

> 仓库里已经包含了 MediaPipe 的 wasm 与姿态模型（约 33MB），所以**不需要**再执行任何安装依赖的步骤，没有 `npm install`。

### 第 1 步：安装 Node.js

只需要 Node 来跑自带的本地静态服务器（十几行代码）。**已经装过就跳过**，用 `node -v` 检查：

```bash
node -v      # 需要 v18 或更高，v20/v22 都可以
```

---

### Windows 安装 Node.js

**方式 1：winget（Windows 10 1809+ / Windows 11 自带，最省事）**

打开 **PowerShell**（开始菜单搜索 "PowerShell"），执行：

```powershell
winget install OpenJS.NodeJS.LTS
```

**方式 2：官方安装包**

1. 打开 <https://nodejs.org/> → 下载 **LTS** 版的 **Windows Installer (.msi)**（64-bit）
2. 双击安装，一路 Next；**务必保持默认勾选的 "Add to PATH"**
3. 安装完成后**关掉再重新打开** PowerShell / 命令提示符

**验证：**

```powershell
node -v
npm -v
```

两条都能打印出版本号（例如 `v22.14.0` / `10.9.2`）就成功了。

> 如果提示「无法将"node"项识别为 cmdlet」，说明 PATH 没生效：关掉终端重开；还不行就重新安装并确认勾选了 Add to PATH。

### 不想装 Node.js？用 Python 也行

## 手机浏览器使用（iPhone / Android）

手机能不能开摄像头，只看**地址是不是 https**，跟手机型号无关：iOS Safari / Chrome 只在
**安全上下文**（`https://` 或 `localhost`）下才会把 `getUserMedia` 交给网页。
用 `http://192.168.x.x:4174` 打开时，浏览器**一定会拒绝** —— 这不是本项目的限制，
换哪个浏览器都一样。（QQ 浏览器自带自己的取景通道，所以它在 http 下看起来「能开」；
那条路不走标准 API，画面进不了本项目的骨架叠加层与计数，别把它当成可用方案。）

### 两条拿到 https 的路

| 方式 | 怎么做 | 优点 | 缺点 |
|---|---|---|---|
| 自签证书（推荐，全程离线） | ① 生成证书 ② 用 `HTTPS=1` 起服务 ③ 手机装证书并设为完全信任（见下） | 画面不出局域网、断网也能用；不用第三方 | 手机要装一次证书；装好之前浏览器会提示「连接不安全」 |
| ssh 隧道（不想装证书） | `ssh -R 80:localhost:4174 nokey@localhost.run`，用终端打印的 https 地址打开 | 不用装证书、不用改手机设置 | 需要外网；网页请求要经过第三方隧道 |

```powershell
# ① 生成自签证书（项目根目录跑一次；Windows 自带 PowerShell 就够，不需要 openssl）
powershell -ExecutionPolicy Bypass -File tools\make-cert.ps1

# ② 起 https 服务（手机与电脑连同一个 Wi-Fi），终端会打印手机直接照抄的地址
$env:HOST="0.0.0.0"; $env:HTTPS="1"; node preview-server.js
```

```
体感健身游戏预览地址： https://127.0.0.1:4174
局域网（手机同 Wi-Fi 打开）： https://192.168.1.23:4174   [Wi-Fi]
```

> 证书落在 `tools/certs/`（**已 gitignore，里面有私钥，别提交**）：`dev.pfx` 给服务器用，
> `dev-cert.pem` / `dev-cert.cer` 给手机装。证书里的地址（SAN）包含 `localhost`、本机名
> 与**生成那一刻的所有局域网 IP** —— 换了 Wi-Fi / IP 变了，重新生成一次即可。
> 想用自己已有的证书：`$env:CERT_FILE="…pem"; $env:KEY_FILE="…pem"; $env:HTTPS="1"; node preview-server.js`。

### 把证书装进手机（用自签证书时必须做）

| 系统 | 步骤 |
|---|---|
| iPhone / iPad | ① 把 `tools/certs/dev-cert.pem` 发到手机（AirDrop / 微信「文件传输助手」/ 邮件附件）② 点开它 → 设置 → 通用 → VPN与设备管理 → 安装描述文件 ③ **设置 → 通用 → 关于本机 → 证书信任设置 → 打开「Motion Fitness Dev」的完全信任**（跳过这步，浏览器照样拒绝开摄像头）④ Safari 打开 `https://<局域网IP>:4174` |
| Android | ① 把 `tools/certs/dev-cert.cer` 传到手机 ② 设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 → 选这个文件 ③ Chrome 打开 `https://<局域网IP>:4174`（仍提示「不安全」时点「继续访问」） |

### 不想装证书：ssh 隧道

```bash
ssh -R 80:localhost:4174 nokey@localhost.run
```

终端会打印一行 `https://xxxx.lhr.life`，手机浏览器直接打开它就能用摄像头
（先在本机按上面的命令把 `node preview-server.js` 起好）。隧道只转发网页文件；
**摄像头画面始终在手机浏览器里本地处理**，MediaPipe 模型也在本地 `vendor/`，
识别结果不上传、视频不离开手机。

### 摄像头诊断面板（打不开时先看它）

摄像头启动失败时，画面上的提示下面会展开一块**「摄像头诊断」**（PC 上也有，默认折叠、不打扰），
逐行列出浏览器此刻的客观事实，最后给一句对应的处置建议：

| 面板里的行 | 看什么 |
|---|---|
| `isSecureContext` / `location.protocol` | 手机上的头号原因：不是 https → 浏览器一定不给摄像头 |
| `navigator.mediaDevices` / `getUserMedia` | 浏览器有没有这个能力（老浏览器与非安全上下文都是「否」） |
| `getUserMedia` 错误 | `NotAllowedError`（权限被拒）/ `NotFoundError`（没摄像头）/ `NotReadableError`（被占用）… |
| `videoWidth × videoHeight` | 摄像头到底出没出画面 |
| `video` 属性 | `playsinline` / `muted` / `autoplay` 是不是都在 |
| 处置建议 | 按上面的事实给一句中文做法（例如「换 https 打开」「改权限」） |

### 手机上的全屏与「添加到主屏」

- 电脑 / Android：全屏按钮走标准 `requestFullscreen()`，放大的是**视频框**本身，
  HUD、判定进度条、手势圆环全部保留。
- iPhone：**iOS Safari 没有元素级 Fullscreen API**（`requestFullscreen` 在 iPhone 上不存在，只有 iPad 有），
  所以没有原生能力时自动退到 **CSS 伪全屏**：视频框铺满视口、页面其余部分盖住，叠加层照旧保留；
  再点一次按钮、按 `Esc` 或转屏都能退出。
- 想要**真·无浏览器栏**：Safari「分享 → 添加到主屏」，从主屏图标打开（PWA，`display: standalone`）——
  这是 iOS 上最接近真全屏的正规做法（图标在 `icons/`，由 `tools/make-icons.py` 生成）。
- 手机竖屏时动作页会盖一层「**请把手机横过来**」的提示（识别是横向画面），横过来自动继续；
  主页在竖屏下正常浏览，不打扰。

### 已知限制

| 限制 | 说明 |
|---|---|
| `<video>.webkitEnterFullscreen()` 会丢叠加层 | 它是 iPhone 上唯一的原生视频全屏，但只放大视频、不带我们的 HUD / 判定进度条 / 圆环，所以本页不把它当主路径 |
| 自签证书浏览器会提示「连接不安全」 | 证书装好并在「证书信任设置」里完全信任之后就不再提示；也可以改用隧道 |
| 换 Wi-Fi 后 https 打不开 | 证书 SAN 里是**生成时**的局域网 IP，IP 变了要重新跑一次 `tools/make-cert.ps1` |
| 手机默认用轻量模型 | 按 UA / 核数 / 屏幕判定为「手机或低配」，首次打开用轻量模型与 960×540@24 的摄像头；**用户自己在设置里改过模型就永远按用户的来** |

## 运动前校准

选好动作后，画面里会出现一个**虚线的人体剪影**：一条干净的外部轮廓线（不是骨骼连线），这就是你的姿势目标；
画面上方还会有一行文字提示，直接告诉你「进入虚线轮廓内」。校准面板会逐项打勾：**只有「识别到人体」和「全身入镜」两项是必须的**（✓ 达标、○ 没达标就会拦着开始）；
其余五项用「·」标出，只是**建议**——照着调整会让识别更准，但不影响开始。

| 检查项 | 含义 |
|---|---|
| 识别到人体（**必须**） | 摄像头看清你了 |
| 全身入镜（**必须**） | 头顶到脚都在画面里，没被画面边缘切掉 |
| 距离合适（建议） | 身体在画面里的大小合适（太远/太近会给方向提示） |
| 左右居中（建议·仅站姿） | 身体落在轮廓中间（躺姿不检查这一项） |
| 高度合适（建议） | 身体在画面的上下位置合适 |
| 机位正确（建议） | 正面动作（自重深蹲 / 相扑深蹲 / 深蹲跳 / 开合跳 / 波比跳）要**正对**镜头，其余要**侧对**镜头 |
| 保持不动（建议） | 站定不动识别更稳（不站定也能开始） |

**每个动作都有自己的剪影**（按动作的机位与体态自动选用），摆好姿势照着轮廓对就行：
正面动作（自重深蹲 / 相扑深蹲 / 深蹲跳 / 开合跳 / 波比跳）是正面站姿剪影，站姿类动作是侧面站姿，
俯卧撑类（含登山者）是**侧面的俯卧撑起状态**（直臂撑地），平板支撑是**侧面小臂撑地的俯卧状态**，
臀桥 / 卷腹 / 仰卧抬腿 / 死虫式这些躺姿动作是**侧面的仰卧屈腿状态**（仰卧、屈膝、双脚踩地）。
侧拍时轮廓会跟着你的朝向自动左右翻转。

**必须的两项达标**并保持约 0.6 秒后，**虚线轮廓会立刻消失**（这就是「已识别到你的全身」的信号），
随后自动 3-2-1 倒计时开始计数，不需要再点任何按钮。
一组结束时会回到校准：这一轮**同样在识别成功的那一刻就把轮廓收起来**，由你点「开始训练」（或按空格）开始下一组 ——
这样可以先休息、看看小结，不会被立刻拽进下一组。

**虚线轮廓的显示规则（所有动作统一，只有一条）**：**轮廓只在「你还没就位」的时候出现，一就位就消失。**

| 什么时候 | 轮廓 | 为什么 |
|---|---|---|
| 还没识别到人体 | 画（亮天蓝，画面上写「没找到你」） | 告诉你人要站在画面里 |
| 识别到了、但还没就位 | 画（亮琥珀 + 具体差在哪） | 引导你走进轮廓（挪近/挪远、往左/往右、转正/侧身） |
| 就位判定通过并保持住（含一组做完的休息态） | **不画** | 你已经站好了，轮廓没用了，留在画面上只会挡住人 |
| 倒计时 / 正在计数 / 暂停 | **一律不画**（一帧都不画） | 这几态是「在运动」，画面要让给骨架、角度标注和进度条 |
| 就位后又站偏了 | 又画（超过 0.3 秒的抖动宽限才重新出现） | 重新把你领回轮廓里 |

> 训练中**绝不会**再出现虚线轮廓：主循环里对「倒计时 / 计数 / 暂停」三态有一道硬性兜底
> （`session` 属于这三态时直接 `outline = null`），并且有测试把 19 个动作的每一帧都翻一遍来钉住这条不变量。
> 想自查的话，🐞 指标面板里有一行「**虚线轮廓 ✓/✗**」，显示这一帧到底画没画；就位后应该是 ✗。

> 站不到位时，画面上方的文字提示和校准面板里都会直接写出该做什么（例如「往镜头方向挪一点」「往右挪一点」「请正对摄像头」），
> 不会出现"不知道哪里不对"的情况。
> 站姿动作（自重深蹲 / 箭步蹲 / 波比跳这类）与躺姿一样**容忍出画约 3%**：前后脚拉开、脚尖贴着边缘都不会被拦，
> 只有身体明显有一边在画面外才提示「往后退半步或往里挪一点（不用站到正中间）」。
> 躺着的动作（俯卧撑 / 平板支撑 / 臀桥 / 卷腹这类）同样只要求「身体大致在画面里」，而且**允许出画约 3%**：
> 躺着时身体横跨整幅画面，头顶或脚碰到边缘完全不影响识别；躺姿也**不再要求「左右居中 / 高度合适」**
> —— 横躺的身体本来就不会正对画面中央。距离按**身体长度**判断，不用站起来。
> 想重新校准：点画面下方的「重新校准」按钮；每一组结束后也会自动回到校准。

## 动作主页与动作页

**主页**：进站先看到一个大大的 **🖐 开始体感训练** 按钮，下面才是分类动作墙 ——

- 点那个大按钮 → **全手势流程**（见下一节）：打开摄像头 → 视频框全屏 → 手势菜单 → 用手选动作。
- **主页与动作页都是「高饱和深色渐变」底**（用户要求「整个网站的 web 主页的底色不好，太暗了，请改为鲜明的颜色，

  **背景**要改为主页那套『紫 / 青 / 薄荷渐变』色」）：深紫 → 青蓝 → 薄荷深绿三段渐变 + 三团品牌色光晕
  （`body.is-home, body.in-workout, .modal-card` 这**一个**作用域里的 `--home-bg-1/2/3` 与 `--home-glow-1/2/3`，
  **主页 / 动作页 / 弹窗面板三处共用同一份数值、只此一处定义**），渐变**钉在视口上**（滚动不跳），
  卡片 / 描边 / 顶栏图标按钮 / 侧栏 / 视频框外围的 letterbox 也跟着提亮一档

## 🖐 全手势操作（首页「开始」→ 视频界面里的手势菜单）

> 用户要求：「我希望把界面改造为**全手势操作**。请在首页增加一个**大的『开始』按钮**，
> 点击后就打开摄像头进入到**全屏的视频界面**。在这个视频界面里面，给出**手势选择菜单**，
> 也采用**手进入圆环 3 秒**的方式来进行选择，菜单项就是各项运动，选择之后则直接进入到全屏的各项运动界面，
> 在各项运动中如果退出，则回到菜单页面，如果在菜单界面退出则回到网页首页。」

**整条链路（键盘鼠标都不用碰）**：

| 你现在在哪儿 | 做什么 | 会发生什么 |
|---|---|---|
| 网页首页 | 点最上面那个大按钮 **🖐 开始** | 打开摄像头 → **视频框全屏** → 进入手势菜单（第一级：分类） |
| **菜单第一级**（5 个分类） | **手从圆环外面**抬进来、放进某一格**停住 3 秒** | 圆环顺时针走满一圈变绿 → 进入这个分类（第二级）；指着某一格约 1 秒时会先把名字念出来 |
| **菜单第二级**（该分类的动作） | 手掌停满 3 秒 | 语音报出动作名 → 直接进入该动作的全屏训练界面（校准完成自动开始这一组） |
| **顶部左角那颗「返回」** | 手掌停满 **5 秒**（或点它） | 第二级 → 回第一级（分类）；**第一级 → 回网页首页**（并退出全屏）。图标/样式和别的「返回」完全一样，只是「往上一层」的含义不同 |
| **需要翻页时** | **双手同时向上挥两次 = 上一页；向下挥两次 = 下一页** | 翻一页（循环；页码那一行写着「第 N / M 页」）。也可以把手掌放进顶部那两颗「上一页 / 下一页」圆环停 **5 秒**，或点页码、按 ← / → |
| **某个动作里** | 手或脚伸进**右上角**圆环，保持 3 秒 | 这一组正常收尾结算 → **回到手势菜单的第一级第 1 页**（全屏留着，接着挑下一个动作） |
| **手势菜单里** | 按 `Esc`（或点右上角的 🏠） | **回到网页首页**（并退出全屏） |

- **一页最多一行、每行最多 6 个格子**（用户要求：「把每个运动圆环的大小再进一步缩小，每行最多放 6 个圆环，
  但是把『上一页』、『下一页』这两个圆环也放在这一行（如果需要显示的话）」），
  **「↩ 返回」常驻在右上角、不占格子**（用户要求「固定在画面上，不参与翻页」，后来又要求
  「把菜单界面中的退出圆环始终放在右上角，且各界面退出圆环的位置和大小都保持一致」）——
  格子多了，圆环**跟着变小**（直径 = 格子宽 × 0.86，一处定义）；6 格一行之后，第一级 5 个分类、
  第二级全部动作（最多 6 个）都能**一页放完**，只有格子更少的窄屏才真的需要翻页：

  | 视频框尺寸 | 选项圆环 | 翻页圆环（上一页 / 下一页） | 名字字号 | 每页 |
  |---|---|---|---|---|
  | 1280×720 | **≈176px**（上一版 211px） | **≈176px**（就占这一行的格子，和选项同大） | **≈26px** | 6 个（无分页）/ 4 个（有分页） |
  | 1920×1080（全屏常见） | **≈264px**（上一版 317px） | **≈264px** | 40px | 6 个 / 4 个 |
  | 竖屏手机（320×700） | 自动减列 + 放宽到两行（一格至少 120px） | **≈129px**（2 列 2 行：4 格） | 跟着直径 | 无分页 4 个 / 有分页 2 个 |

- **「↩ 返回」在右上角，和动作页的「退出」圆环一模一样**（用户要求：「把菜单界面中的退出圆环始终放在右上角，
  且各界面退出圆环的位置和大小都保持一致」）：
  - **位置 / 尺寸同一处定义**：`exitRingLayout()` 一个函数算出圆心（`ringCenter('corner', …)`：右边距 18px、
    上边距 16px，再叠加刘海 / 状态栏安全区）和直径（`ringPx('corner')` = CSS 变量 `--ring-px`，1280×720 上 ≈134px）；
    动作页那颗「退出」和菜单这颗「返回」**摆也走同一个 `layoutExitRing()`**，所以两者屏幕坐标 / 尺寸逐像素相同；
  - **圈里只有一颗线条箭头**（和退出图标同一颗，字号 = 直径 × 62%），文字含义在 `title` / `aria-label` 上；
  - **常驻、不跟换屏滑动**：它在 `.menu-screen` 之外（和猫爪层一样），翻页 / 返回的整屏滑动不会把它带走；
  - **蓄力 5 秒**（`MENU_NAV_HOLD_MS`，和翻页圆环一样长）；第一级 = 回网页首页、第二级 = 回分类（`selectFromMenu`）。

- **「上一页 / 下一页」也在选项那一行**（用户要求：「把『上一页』、『下一页』这两个圆环也放在这一行」）：
  - 这一行 = **`[◀ 上一页] + 选项 + [下一页 ▶]`**，**格子总数 ≤ 6**；真的要翻页时才出现
    （单页时整行都是选项、页码那一行也不出现）；
  - 翻页时每页选项数 = 格子数 − 2（`menuPerPage()` / `menuPageInfo()` / 页码文案 / 翻页循环一起自洽）；
    1280×720 上 6 格、不翻页；700×400 上 5 格 → 每页 3 个；320×700 上 4 格 → 每页 2 个；
  - 只有 2 列的小屏第一行排不下「上一页 + 选项 + 下一页」，改成按**整页**首 / 末格摆
    （左上 = 上一页、右下 = 下一页），选项用中间那些格子；
  - 翻页圆环和选项**同一套直径 / 字号 / 判定半径**（都从 `menuBandGeom().dia` 来，绘制 = 判定）；
  - 圆环直径跟着格子走（格子宽 × 0.86；1280×720 上 Ø176px，比上一版的 Ø211px 小一截；一格至少 120px）。

- **翻页 = 双手同时挥两次**（用户要求：「双手向上挥动两次则向上翻页，双手向下挥动两次则向下翻页」，
  方向按键盘 PageUp / PageDown 的口径）：**向上挥 = 上一页、向下挥 = 下一页**。
  为什么是「双手 + 两次」：单手挥手在生活里太常见（抬手、挠头、换姿势），
  而「两只手一起、同一个方向、连着挥两下」基本只有「我要翻页」才会做 —— 误触概率极低。
  判定口径（`updateMenuSwipe`）：

  | 规则 | 口径 |
  |---|---|
  | 两只手都要看见 | 只有一只手挥不算 |
  | 都要在**圆环之外** | 正指着某一格时挥手不算翻页 |
  | 各自挥够行程 | `MENU_SWIPE_TRAVEL = 16%` 舞台高度（1280×720 上约 115px），且要在 `MENU_SWIPE_MS = 550ms` 内完成（慢慢挪不算） |
  | **一次挥动只算一次** | 挥完必须停一下（速度掉到 `MENU_SWIPE_QUIET` 以下并保持 `MENU_SWIPE_QUIET_MS`）才接受下一次 —— 「挥出去再收回来」的回收动作、一次不停的长挥动都不会被算成两次 |
  | 连着两下 | 第二下要和第一下同方向、并在 `MENU_SWIPE_CHAIN_MS = 1.6 秒` 内出现（隔太久就重新数） |
  | 冷却 | 翻完一页 `MENU_SWIPE_COOLDOWN_MS = 1.2 秒`，连挥不会连翻好几页 |

  这一行两端那两颗「◀ 上一页 / 下一页 ▶」是**兜底**
  （摄像头角度不好、手挥不动时照样能翻），只有真的有第二页时才出现；
  鼠标点页码那一行、键盘 ← / →（或 PageUp / PageDown）也都能翻。

- **右上角那颗「返回」和选项行分开**：它在画面角上（和动作页退出圆环同一位置、同一尺寸），
  选项那一行在它下面偏左，两边的判定圈不会互相压住（测试逐个量过）；翻到第几页它都在，一眼看得到。

- **翻页 / 返回都是「整屏滑动」**（用户要求：「把淡入淡出的效果改为完整的滑动效果，比如从主菜单进入核心运动
  菜单，则主菜单的所有圆环全部向左滑出，核心运动的圆环则从右面滑入界面，形成一个整行滑动的效果」）：
  - 换屏时把**上一屏整块**（标题 / 说明 / 页码 + 所有圆环 + 底部提示）克隆进残影层 \`.menu-ghost\`，
    按方向**整块平移出去**；新一屏（\`.menu-screen\`）从另一侧**整块平移进来**；
  - **同距同时长**（滑行距离 \`menuSlideDistance()\` 按舞台宽度算：半个舞台宽 + 圆环半径 + 余量，
    保证最里面那颗（画面中线上那一格）也完全滑出画面；时长 560ms，进出一样），所以看起来就是
    **一整行从右往左推过去**（传送带），不再是原地淡入淡出；
  - 方向按「翻页」的直觉：**下一页 / 进下一层 = 老的一屏往左推走、新的一屏从右边推进来**，
    **上一页 / 返回 = 反过来**；
  - **真实 DOM 立刻重建**（动画只做在克隆出来的残影上），状态和界面永远同步、连续翻页不会乱；
    动画还没播完又触发一次就跳过动画直接切，不叠加；
  - 时间 / 距离都写成 CSS 变量（\`--menu-anim-out\` / \`--menu-anim-in\` / \`--menu-slide-x\`），
    由 app.js 一处给值，CSS 只管动画 —— 不会出现「两处各说一套」；
  - 回网页首页那一路仍是**菜单淡出 + 主页淡入**（\`showHome()\` 必须立刻生效，不能等动画），
    尊重系统的「减少动态效果」（\`prefers-reduced-motion\`）—— 开了就只切不播。

- **不容易误触**（用户反馈：「因为菜单圆环很大，数量又比较多，人站在画面中手很容易误触某个圆环。」）：
  菜单是**大目标 + 满屏**，所以判定刻意做得比「越大越好瞄准」更保守，一共五道：

  | 闸 | 口径 | 挡住什么 | 误触面积（1280×720 实测） |
  |---|---|---|---|
  | ① 判定圈 = 画出来的圆圈 | `MENU_HIT_RATIO = 1.0`（以前 1.15） | 站在画面里手蹭到圆环外沿 | 同一批圆环：26.0% → **19.6%** |
  | ② 起手圈 0.8 倍（迟滞） | 要**进到圈内 80%** 才算起手；已经在蓄力时晃到圈边（≤1.0 倍）不算离开 | 沿着外沿那一圈（占圆盘 36% 面积）蹭过去 | 起手只剩 **12.6%** |
  | ③ 手在动就暂停计时 | 手掌速度 > `MENU_STILL_SPEED`（舞台高度的 30%/秒）时，计时起点跟着往后挪 | 抬手、转身、换姿势时手**从圆环上扫过** | —— |
  | ④ 要从环外进来 | 一只手必须先在**所有圆环之外**露过面（`armed`），才能开始给某一格蓄力 | **进菜单时手正好垂在某一格里**，以前它会默默开始攒 3 秒 | —— |
  | ⑤ 离开后退得更快 | `MENU_DRAIN_MS = 700ms`（别的圆环是 1500ms） | 蹭一下留下来的半格进度 | —— |

  另外把**整块圆环往上放**（上边距 15%、下边距 18%；窄屏 20% / 20%），
  圆环纵向只占画面 **34%~63%**，下方留出一大片**「放手区」**——
  人站在画面里手自然垂下时正好落在这一条里，不会压在某一格的判定圈上。
  想更灵敏 / 更保守，调 `MENU_HIT_RATIO`、`MENU_START_RATIO`、`MENU_STILL_SPEED` 这三个数就行。

- **菜单就是动作库**：第一级取 `localizedCategories()` 的 5 个分类，第二级取 `localizedByCategory()`，
  一处定义；每格是「圆环 + 图标 + 名字」，分类那格多一行「N 个动作」，右上角那颗「返回」有单独的淡样式。

- **翻页：为什么不用挥手，改成两个圆环**（用户反馈：「但是挥手换页的方式似乎也不太好。」）：
  垂直挥手和「伸手去够上面那一排圆环」是**同一个动作方向**，两件事互相打架、也不容易学。
  现在翻页用**和选动作完全一样的交互** —— 把手掌放进选项那一行正上方的
  「上一页 / 下一页」圆环（「返回」已经挪到右上角了，这两颗离下面那排动作圆环有一段距离，不会抢格）：
  ⚠️ 这两颗翻页圆环的蓄力后来**加长到 5 秒**（`MENU_NAV_HOLD_MS`，比选动作的 3 秒还长）——
  用户反馈「返回、上一页、下一页始终在相同的位置，容易在返回之后持续返回」，
  所以宁可慢一点也要「必须真的停在那一格上」；按住不放仍然每 5 秒翻一页，
  而且**触发一次之后必须把手拿出圆环再进来**才会重新计满（一直停在原地不会连触发）。
  鼠标点页码那一行或直接点翻页圆环同样有效，键盘按 **← / →**（或 PageUp / PageDown）。
  只有一页时这两个圆环和页码都不出现，画面干干净净。
- **菜单就是动作库**：第一级取 `localizedCategories()` 的 5 个分类，第二级取 `localizedByCategory()`，
  一处定义；每格是「圆环 + 图标 + 名字」，分类那格多一行「N 个动作」，「返回」那格有单独的淡样式。
- **位置、直径、字号都由 `menuRingLayout()` 按舞台尺寸算**，写进行内 `left/top/width/height/font-size` ——
  判定用的圆心 / 半径与画面上看到的是**同一份数**，所以「看到哪一格」和「程序判哪一格」不会各说一套
  （和右上角退出圆环同一个做法）；列数只看屏幕宽度，所以**每一页的圆环都一样大**，最后一页不满就整行居中。
- **判定手感**：手掌中心（手腕 / 食指 / 小指 / 拇指的均值）+ **3 秒**（`GESTURE_HOLD_MS`）
  + 300ms 抖动宽容；判定半径就是画出来的圆圈（`MENU_HIT_RATIO = 1.0`，起手还要求进到 80%），
  多个圆环都碰到时取**最近**的那一格。
  （那个**退出**圆环是反过来的老问题 —— 手/脚够不到，所以它单独用 `RING_TOUCH_TOL = 1.12` 放宽；
  菜单是「太灵敏」、退出环是「不够灵敏」，两者口径不同是刻意的。）
- **一格一格地选**：手掌移到别的圆环上，之前那一格的进度**立刻归零**（否则会在两格之间攒进度）；
  换一页 / 换一层同样清零，手停在原地也不会误选；翻页 / 返回之后要**重新从环外进来**才认。
- **先念名字再选中**（`MENU_ANNOUNCE_P`）：指着某一格约 1 秒（进度到 28%）就先把这一格的名字念出来，
  能立刻确认「我瞄的是不是它」，不用等满 3 秒才发现瞄错了。
- **图标：一整套线条画**（按 `ui-icon-design` skill 的流程重做；风格原型 **`rounded`**）：
  **19 个动作 + 5 个分类（菜单与主页都用同一张）+ 3 个导航箭头 + 10 个界面按钮**（右上角回主页 / 最佳成绩 / 运动记录、
  搜索、手势开始的手、摄像头占位、运动设定、全屏、关闭、品牌标）全部是线条图标，
  界面里**再也没有用 emoji 当图标**（emoji 只留在成绩记录、要领标题这类**文本**里）。
  - **风格参数（全套锁死）**：`viewBox="0 0 24 24"`、**20×20 活动区居中**（四周留 2px）、
    `stroke-width="2"`、`stroke-linecap/linejoin="round"`、`fill="none"`、颜色 `currentColor`、
    坐标只落在**整数或 .5** 上（避免半像素虚边）、只含 shapes（没有 `<text>`、没有位图、没有写死的颜色）。
    动作图标另外会**按内容缩放进 20×20 活动区**，所以 19 张图的视觉重量一致。
  - **先检索现成图标，命中就用**（skill 的第 2 步）：分类的五个用
    **Lucide 1.55**（ISC 许可）的 `biceps-flexed`（上肢）/ `footprints`（下肢）/ `flame`（核心）/
    `person-standing`（全身）与 **Tabler Icons 3.49 outline**（MIT）的 `stretching`（拉伸）；
    导航用 Lucide 的 `corner-up-left`（返回）/ `chevron-left`（上一页）/ `chevron-right`（下一页）；
    界面按钮用 `house` / `trophy` / `history` / `search` / `hand` / `camera` / `settings` / `maximize` / `x` / `dumbbell`。
    出处与许可写在 `src/icons.js` 的注释里，换图标时查得到来源。
  - **导航那三个圆环里只画图标、不写字**（用户要求「返回，上一页，下一页不要显示文字了，显示图标即可」）：
    图标因此能画满整个圆环（≈ 直径的 62%）并居中；文字只留在按钮的 `aria-label` / `title` 上，
    读屏和鼠标悬停仍然知道哪颗是「返回」、哪颗是「下一页」。
  - **动作姿势图自己画**（库里没有对应动作：`squat` / `plank` / `lunge` / `crunch` / `bridge` 检索命中 0）：
    仍然由四个构建器产出（`buildStand` 侧视站姿/蹲/箭步蹲、`buildLie` 躺撑坐、`buildJack` 正面开合、
    `buildKick` 勾腿），姿势参数集中在 `EXERCISE_POSES` 一张表；绘制时会把**基本伸直的肘 / 膝两段合成一段**，
    元素数从 10 降到 5~10。⚠️ 这条与 skill 的「一个图标最多 6 个元素」有出入：人体姿势是**象形图**
    （一个关节必须两笔），所以这里的上限放宽到 10，换来的是「不看标签也能认出是哪个动作」；
    库里现成的那 18 个图标仍然全部 ≤6。
  - **运动图标 = 实心象形图，界面图标 = 细线**（用户要求：「运动类的图标也重新设计一下，要设计得更大气、
    上档次一些」，并确认「导航类的图标设计得还可以」）：一整套分成两层，但**网格、圆头圆角、`currentColor`、
    坐标落点完全一致**，仍然是同一族 ——
    - 内容层（19 个动作，`.ex-pose--solid`）：描边 **3**（四肢因此是实心的「身体」，不再是火柴棍）、
      **头填实**并按骨架的 **1.7 倍**放大（剪影要有一个明显的头）、象形图**用满 20×20 活动区**，
      菜单圆环里的图标也跟着放大一档（圆环直径的 38%）；

    `preview.html` 预览页 + `_preview.png` 拼图，含 16 / 24 / 48 / 64px 多尺寸抽查），
    可以逐项核对「48px 下不看标签认不认得出、整排粗细是否一致、16px 下关键特征糊没糊」。
    自动化那侧由 `tests/test-page.mjs` 钉住上面的每条规格（网格、活动区、坐标落点、无 `<text>`/emoji、
    19 张两两不同、躺姿 / 站姿构图对得上、分类与导航图标取自库且元素 ≤6）。

- **全屏只放大视频框**（`#stage`，和右上角那个全屏按钮同一个动作），菜单铺在视频上，
  运动相关的面板（侧栏、工具栏、HUD、判定进度条）在菜单模式下全部收起，画面干净。
- **菜单里不记调试帧**（那时还没有动作）；在菜单里按 Ctrl+H 打开「记录调试数据」后，
  选中动作开始训练就会开始记 —— 省得进了动作再回头开开关。
- 摄像头打不开 / 设备不支持时：屏幕上直接给一句说明，并让你从下面的动作库挑（不会卡在一个黑屏菜单里）。

**画面左上角的两个大数字**：**次数**（计时类动作是**秒数**）在最上面，**分数就紧贴在它下面** ——
用户要求「分数要放在和次数靠近的地方，比如在次数下方，而且要字体要用不同的颜色」，
所以分数是**金色（`--score`）**、和白色的次数、青色的目标进度环都不一样，一眼就能分清哪个是分。
次数和分数**共用一套跳动反馈**：计上一次、要领加分、每秒 +1 分时两个数一起跳一下。
右下角那个圆环只显示**本组目标进度（%）**。

## 🟩 判定进度条（画面上那条一格一格点亮的线条图标链）

动作页画面上**一直显示**一条判定进度条（居中，宽度上限 **880px**，并且**两侧用 `--bar-side-space` 收着宽度**；
图标高约 **44~60px**）：这个动作的关键帧被摊成几格，每格画一个**火柴人线条图标**，
表示「到这一步身体应该是什么姿势」。每识别到一个姿态就点亮一格，一眼就能看到「已经认出来了什么」，
**每完成一次动作就清零**，下一轮从头再走一遍。

> **用户要求「把所有运动的进度条都缩短一点，高度也变小一些」**：以前是「宽度铺满约 95%、图标 58~82px」，
> 现在整条由两个 CSS 变量推出来 —— `--criteria-icon-h`（图标高 44~60px）决定高度、
> `--bar-side-space`（左边距 + 圆环直径 + 间隙）决定两侧要让出多少，所以**改一处整条一起收**，
> 底部提示条让位用的 `--criteria-bar-h` 也从同一个变量算出来，不会两处对不上
> （`tests/test-page.mjs` 逐条钉着这几个关系）。

以箭步蹲为例（格子里就是代码里的真实阈值）：

```
① 站直      ② 迈步      ③ 蹲下      ④ 后膝下沉   ⑤ 回位（计次）
≥145°      ≤146°      ≤138°      ≤146°      站起来
 人形        人形        人形        人形        人形
 ✓          ✓          ✓          ✓          ⏳
```

> **链上每一格都是「计一次数必须满足的条件」，最后一格就是计次那一刻** ——
> 所以「所有关键帧都做完了」= 这一次已经计上了，不会出现「都做对了却没计次」。
> 不影响计次的判据（深度 / 满分、时间类）**不进进度条**，它们作为补充判据列在「📐 关键帧判据与判分」弹窗里对应的那一格下面，
> 分数照旧按深度给（`tests/test-detectors.mjs` 会逐动作验证「链走完」与「计次」相差 ≤250ms）。

- **两种状态**：**没识别到人**时整条是灰的（尚未开始）；**识别到人并且在计数**时变成彩色（已经开始工作）。
  「做到 / 没做到」靠**颜色**分辨，一眼就能分出来：没做到 = 虚线灰框 + 又细又淡的灰线条；
  已做到 = **实心亮绿底**（`rgba(74,222,128,0.26)`）+ **实线绿框** + **加粗亮绿线条**（stroke 1.2 → 2.4）+ 整格外发光；
  正在等的那一格 = 琥珀色粗描边 + 轻轻呼吸。
  > **用户要求「检测到关键帧之后不要再打钩了，有颜色的变化就可以了，简化一下」**：
  > 以前做到的格子右上角还挂着一个 48px 的对勾徽标，现在**整个去掉了**（进度条上没有任何 ✓），
  > 只留颜色变化 —— 顺手把绿色底色从 0.22 提到 0.26，免得少了那枚勾之后「做到了」变得不明显。
  > `tests/test-page.mjs` 会断言进度条里**再也找不到对勾**，同时断言颜色那三重区别都在。
  > （右侧「要领清单」里每一项的打勾是另一个元素、带着文字说明，没有动。）
  识别本身会抖，所以短暂丢帧（0.7 秒以内）不会闪成灰色，也不会清掉进度。
- **格子上只画线条图标**：每个图标都是按这一格的姿态画的火柴人 ——
  「前膝屈角 ≤ 138°」就画一条膝角 138° 的腿；「髋角 ≥ 170°」就把臀桥画成肩-髋-膝一条直线；
  「离地高度 ≥ 0.035×画面高」就画成跳起来；俯卧撑这种撑地动作则让**手固定在地面上、身体高度由肘角决定**
  （肘越弯身体越低）。为了让 159° 与 148° 这种细微差别也看得出来，画的时候把弯曲幅度放大了一点，
  但**顺序与判据严格一致**（判据越难画得越极端）。
- **图标本来就能区分就不写数字；实在像就标出度数**：同一个动作里有两格用同一个关节角、而两个度数相差
  ≤12°（画出来几乎一样）时，这条链上所有该关节角的格子都会在图标里**标出判据的度数**——
  俯卧撑就是典型：`俯撑 → 159° → 148° → 161°`（否则这几个度数画出来几乎一模一样）。
  深蹲这种本来就一眼能区分的链（176°→135°→112°→149°）不标数字，画面上不会全是数字。
- **臀桥的三个关键帧**（用户指定的顺序）：`屈腿仰卧 → 曲腿腰臀顶起 → 恢复屈腿仰卧`。
  第 1 格和第 3 格姿势本来就一样（都是屈腿仰卧），所以**第 2 格加向上箭头、第 3 格加向下箭头**，
  一眼就能看出「这一格是往下回到地面」。**计次发生在「落回地面」那一刻** —— 也就是第 3 格点亮的同一刻。
- **鼠标移到某一格上 → 进度条上方会显示这一格的判定标准**（例如「蹲下 · 前膝屈角 ≤ 138°」），
  顺便带上这一格能拿多少分，松开鼠标就收起来；平时画面上只有图标和分数，不占地方。
- **一格是怎么亮的**：只看「下一格」，所以必须按顺序一格一格走，不会跳格；已经亮的格不会退回去。
  格的判定线优先用**识别器自己的动态线**（深蹲的 standLine、俯卧撑的 backLine、箭步蹲的 exitLine、
  臀桥的 topLine / bottomLine（髋角，跟着你自己躺平的读数走）/ atBottom、通用屈伸类的 progress 比例线），所以「界面说到线了」和「识别器判到位了」永远是同一条线。
- **最后一格一定看得见**：通用屈伸类的「回位」用的是识别器自己的比例线（`progress ≤ 0.16`），
  图标则按弹窗里那条真实判据画（例如「膝屈角 ≥ 157°」，画成腿还差一点没伸直），
  刻意与第一格「站直（176°）」画得不一样 —— 否则「画得一模一样就合并」的规则会把它吃掉，
  变成「进度条满了、却没计次」（这个坑真的踩过，`tests/test-specs.mjs` 现在逐动作守着）。
- **一次动作完成 → 整条链点亮并保持 0.65 秒，然后清零重来**：识别器计上一次的那一刻，
  进度条会把整条链补满（哪怕个别格的判据刚好卡在临界值上），让你明确看到「这一轮走完了」；
  0.65 秒后自动清零，下一轮从第一格重新走。半程动作（没计上次数的那种）同样走完 + 清零。
- **分数就写在关键帧里（字体做大）**：每个动作的分都**分配到具体的关键帧**上（分配表见 `src/specs.js`
  的 `STEP_STAGE`）—— 深蹲 = 站姿 4 / 开始 6 / 计次 21 / 回位 8 + 整轮满分 6；
  臀桥 = 仰卧 5 / 顶起 20 / 落回 8 + 满轮 6；俯卧撑 = 俯撑 5 / 开始 7 / 计次 14 / 回位 8 + 满轮 6。
  还没拿到时，格子上用**灰色小字**标出「这一格可得多少分」；**真达标拿到分**时，换成**大号亮黄色数字**
  （并垫一层深色底、闪一下），所以「动作做得标准不标准」在关键帧上直接看得见。
  计时类的每秒加分也记在最后一格上，会一直往上加。
- **配套反馈**：亮一格会轻响一声（逐级升高，最后一格补一个高八度）；加分时那一格闪一下，
  同时画面上方飘一下「+N」。分数只在识别器真正给分的那一刻出现，不会因为「姿势看起来对了」就提前跳分。
- **进度条不会抖**：格子是**一次性建好的**，之后每一帧只改「该改的那一格」的 class 和数字。
  以前每次加分/点亮都重建整条 HTML：元素被换掉，颜色过渡、呼吸和分数弹出动画都会**从头再放一遍**，
  一秒一次（计时类每秒加分）就成了肉眼可见的抖动。现在状态没变时**一次 DOM 写入都不会发生**
  （`tests/test-app.mjs` 用「class 实际变化次数 = 0」「元素始终是同一批」「渲染时不写任何影响布局的内联样式」三条断言守着），
  上方「本帧 +N」牌子的高度也固定住，出现时不会把整条进度条顶下去。
- **状态变化一律不改几何**（用户第二次反馈「运动时进度条抖动得很厉害」，查下来是动画在动尺寸/位置）：
  - 三种状态（未做到 / 已做到 / 正在等）的格子**边框宽度都是 1px** —— 以前「正在等」用 2px 边框，
    格子内容区会窄掉 2px，里面的图标跟着缩放一下，每点亮一格就抖一次；
  - 「正在等」不再 `translateY(-2px)`，改成**外发光当粗描边**（`box-shadow: 0 0 0 2px`），呼吸动画只改光晕；
  - 「刚点亮」的闪动从「放大 9% 再弹回」改成**纯光晕闪一下**（格子里的图标不会跟着放大缩小）；
  - 一格做完时整条的提示**不再缩放整条**（这条有 1180px 宽，`scale(1.02)` 就是左右各撑开十几像素，每做完一次抖一下），
    只闪边框与光晕；
  - 分数药丸固定最小宽度并居中：从 `+0` 涨到 `+120` 时不会一秒一变宽、把药丸整体往左推。
  这些约束都写进了 `tests/test-page.mjs`（边框宽度三态一致、关键帧里没有 `transform`、过渡里不含
  `transform/width/height`），以后改样式不会再把这些动效加回来。
- **各动作走几格**（画出来一模一样的格子会自动合并，避免「假两步」）：
  深蹲 4 格（站直 → 半蹲 → 深蹲 → 回位）；箭步蹲 5 格（站直 → 迈步 → 蹲下 → 后膝下沉 → 回位）；
  俯卧撑 4 格（俯撑 → 开始下沉（自己的顶位 − 15%）→ **到计次线**（自己的顶位 − 30%，即肘角 ≤148°）→ **回到起始位 = 计次那一刻** —— 几条线都跟着自己的顶位走，见下面「俯卧撑」一节）；
  跪姿俯卧撑 4 格（跪撑 → 开始下沉 → **到计次线**（肘角 ≤155°，比标准俯卧撑松 7°）→ **回到起始位 = 计次那一刻**）；
  跳跃类多一格「起跳」（整幅图离地：深蹲跳用的是 **≥ 0.035×画面高**）；波比跳 4 格（站直 → 下蹲 → 俯撑 → 起跳）；
  臀桥 3 格（屈腿仰卧 → 腰臀顶起（**髋角 ≥ 170° 且 膝角 55°~130°**）→ 落回屈腿仰卧，**落回那一刻计次**）；
  平板支撑按「撑起来 → 离地 → 手贴地」走（计时类没有计次，链条以姿势到位收尾）；
  仰卧类（反向卷腹 / 抬腿）按躯干卷起或腿抬起的幅度走，最后回到起始位计次；
  **卷腹另有三格关键帧**（屈膝躺下 → 卷起 → 卷到位，判据按用户给的模型重做过，见下面「卷腹」一节）。
- **数值来源同一处**：图标与进度条用的阈值、「📐 关键帧判据与判分」弹窗、识别器判定**完全是同一批常量**
  （见 `src/specs.js` 的 `specStages` 与 `src/icons.js`），不会出现「进度条说到了、但没计上」的不一致。
  `tests/test-specs.mjs` 会逐格核对图标里的角度、检查图标不越界、并用合成骨架走一遍动作，
  验证进度条确实一格一格前进、浅动作不会走到最后一格。

## 🖐 一组结束后的手势圆环（退出 / 再做一次）

一组做完（达标自动收尾，或自己点「结束本组」）之后，画面上会浮出**两个大圆环**：
**左边「退出」**（回到动作主页）、**右边「再做一次」**（计数、分数、要领清单全部清零，马上重新开始这一组）。
刚练完手上都是汗、离键盘也远，这两个最常用的选择不该逼你去点屏幕。

- **所有动作都一样**：计数的（深蹲、俯卧撑、臀桥…）和计时的（平板支撑、两种体前屈）做完一组都会摆出这两个圆环，
  自动达标收尾和自己点「结束本组」两条路也一样 —— 不存在「某些动作做完没得选」。
- **怎么用**：把**任意一只手掌**（左右手都行）放进圆环**中央**，保持 **3 秒**——
  圆环会**从 12 点开始顺时针**一圈一圈填满并转成绿色，填满那一刻就触发；手提前拿开，进度会退回去。
- **3 秒是刻意选的**：抬手、路过、犹豫一下都不会误触；圆环中央的判定区大约是环半径的 60%，
  擦到边缘也不算。
- **鼠标/触屏点一下圆环同样有效**（手感一样：点下去也会响一声），键盘还有 `Esc`（结束本组）和 `R`（重置计数）两条老路。
- **画面镜像时手掌位置跟着翻**：镜像预览下你看到的画面是左右翻的，圆环没有翻，所以判定会跟着镜像设置走，不会出现「手伸向左边却触发了右边」。
- **圆环不会被「人不在轮廓里」收掉**：卧姿类动作（臀桥 / 卷腹 / 平板 / 坐姿体前屈）做完时人本来就不在站立轮廓里，
  这时候圆环照样留着、不会一闪就没。**只有真的要开始下一组**（自动开始或点开始）、换动作、回主页时才收起。
- **圆环摆出来时画面上方只留一条提示**（「把手掌放进圆环中央保持 3 秒」）：校准提示条会临时让位，两条提示不抢位置
  （但它的**文字照样会更新**，所以圆环一收起来看到的就是当前该说的话，不会留着上一帧的旧话）。
- **点「退出」＝真的离开**：回主页的同时**自动退出全屏**（用户要求）—— 不会把你留在一个放大版的主页上。
- **一次只会触发一个**：两个圆环各自计时，谁先停满 3 秒就触发谁（一只手依次停留也不会误触另一个）。

### 右上角常驻的「退出」圆环（运动中途就能退）

> 用户最早要求：「画面左下角划一个『退出』圆环，手或者脚进入之后保持 3 秒则退出运动以及全屏状态。
> 圆环的动画效果和运动结束后的退出圆环保持一样。」
> 后续又要求：「左下角，和右上角的圆环成对角的状态，直径还可以再大一点，
> 右上角的圆环直径可以小一点，**各个圆环大小一样，保持对称**；而且**只在打开摄像头的时候显示**。」
> 最后明确判定口径：「退出圆环是检测**手掌进入圆环内部**三秒，或者**脚进入圆环内部**三秒。」
> 再后来 HUD 改版（进度圆环挪到计次的位置）之后又要求：「**把『退出』这个圆环从左下角移到右上角。**」
> —— 所以它现在贴在**右上角**，和左上角的名称胶囊同一条基线。
> 最后定了判定口径：「手掌或脚**的一部分进入**我认为就要开始沙漏计时，保持 3 秒后退出。**一部分进入即可触发**。」
> 后来又反馈：「**只要脚尖进入圆环就要开始沙漏计时，现在感觉要脚踝进入才开始计时，并不好。**」
> 最后又反馈：「**感觉目前必须是脚踝和手腕进入才开始 3 秒计时，这个不好，请优化。
> 改为只要手和脚有一部分进入就可以开始 3 秒计时了。**」

**为什么以前不灵敏**（四轮反馈查出来的，十条全修了）：

| 原因 | 以前 | 现在 |
|---|---|---|
| ① **要「中心」进环，不是「一部分」进环** | 判定只看一个代表点（手掌中心 / 整只脚的中心），而且要求它落在判定半径内 —— 用户是拿**手指尖**去够圆环的，指尖进去了、掌心还在环外，计时永远不开始 | **逐点判定**：手/脚上的**任意一个点**（手腕 / 食指 / 小指 / 拇指 / 踝 / 脚跟 / 脚趾尖）进圆环就开始计时（`touchSamples` × `anyTouchInRing`） |
| ② **判定区比圆环小得多** | 判定半径 = 直径的 **0.30**（环半径的 60%）：屏幕上半径 70px 的圆环，只有中间 **42px** 的小圈算数 | 判定半径 = **圆环画出来的那个半径**（0.5 × 直径）：**点在圆圈里面就算**，和看到的圆环完全一致 |
| ③ **可见度门槛太高 + 要求至少 2 个点** | 门槛 **0.4**，而且手腕/食指/小指/拇指里**至少要有 2 个**过门槛才算手 —— 手/脚伸到**画面边角**（圆环正好在角上）时可见度本来就偏低，结果整只手/整只脚被丢掉 | 门槛降到 **0.3**，而且**只要有一个点可用就算**（手腕本身很稳） |
| ④ **成绩会被一秒清零** | 手离开超过 0.3 秒就 `since = 0` —— 停了两秒多，手抖出去 0.4 秒全部作废 | 改成**按时间累积、按时间慢慢退**：短暂滑出去（0.3 秒宽限期内）一点都不掉，真的拿开才在约 1.5 秒里退完 |
| ⑤ **看不出「没识别到」还是「差一点」** | 只有进圆环才有反应，手在旁边一点时画面毫无变化 | 手/脚落在判定半径 **2.2 倍**以内时，圆环**亮一下**（`.near`：青色光晕，只改颜色不动尺寸），一眼就知道「摄像头看得见我的手，再往里挪一点」 |
| ⑥ **脚的关键点在画面边角会被整批丢掉** | 脚跟 / 脚尖与手指尖共用 **0.3** 的可见度门槛 —— 脚要够到画面角落通常是斜着伸过去，这两个点的可见度实测常只有 **0.2 上下**（鞋尖被裁掉、脚背朝镜头都会被压低），于是**整只脚只剩脚踝一个点可用**：脚尖明明在环里，判定却什么都不知道，人只好继续往里塞 —— **这就是「感觉要脚踝进入才开始计时」的真正原因** | 脚单独一档更宽松的门槛 **`FOOT_VIS_MIN` = 0.15**（手仍是 0.3）：脚尖/脚跟只要有一点影子就算数 |
| ⑦ **脚是「一片」，判的却是「一个点」** | 只比较**关键点**到圆心的距离：脚尖搭在圆环上、脚尖 / 脚跟 / 脚踝恰好都在圈外（脚那一段穿过圆环）时，一个点都不在环内 → 不计时 | 加了**线段判定**：同一条手/脚上的点两两连成线段，圆环和**任意一条线段相交**也算进去了 —— 「脚尖在环里、脚踝还在环外」当场成立 |
| ⑧ **脚尖点彻底量不到时没人替它说话** | 脚尖点丢了就是丢了，脚掌那一头等于不存在 | 量不到时**自己估一个脚尖**（`ghost`，见 `FOOT_TIP_FROM_SHIN` / `FOOT_TIP_FROM_HEEL`），并且估算点离脚踝太远就**宁可不估**（`FOOT_TIP_MAX_SHIN`，防止脚跟被误检到画面外时凭空伸进圆环） |
| ⑨ **手腕 / 脚踝以外的点根本产生不出来** | 手 / 脚的外延全靠 MediaPipe 的**指尖、脚跟**关键点（17~22、29~32），而 Pose 模型对这几个点本来就是**估出来的**：手/脚伸到画面边角时它们常常落在手腕 / 脚踝附近，或者直接被可见度门槛丢掉 —— 于是「手的一部分进入」实际只剩手腕一个点可用，脚尖更是等于不存在 | 按**肢体方向自己把外延补出来**（用可靠得多的肘 / 膝当参考）：手掌点 = `手腕 + k × (手腕 − 肘)`（k = `HAND_EXT_K` = 0.45 / 0.9），脚尖点 = `脚踝 + k × (脚踝 − 膝)` 与 `脚踝 + k × (脚踝 − 脚跟)`（k = `FOOT_EXT_K` = 0.5 / 1.0）。这些点**只参与圆环判定**（不画在画面上、也不参与动作识别），并且各自有「别伸太远」的上限（`HAND_EXT_MAX_ARM` / `FOOT_TIP_MAX_SHIN`） |
| ⑩ **手/脚贴在圆圈边上、差一点点** | 判定半径就是画出来的半径：手/脚**贴在圆圈外侧一点点**（比如 1.05 倍）就完全不算，人只能继续往里塞 | 这个退出圆环的判定半径再放宽 **12%**（`RING_TOUCH_TOL = 1.12`）：贴着圆圈外沿也算进去了。**只放宽这一个圆环**，「一组结束后」的两个大圆环仍严格按画出来的半径判（它们本来就是「把手掌放进圆环中央」的设计） |

- **「一部分进入即可触发」是怎么实现的**：把每只手（手腕 / 食指 / 小指 / 拇指）和每只脚（踝 / 脚跟 / 脚趾尖）
  都当成独立的采样点，**任意一个点落进圆环的圆圈里**（或者整只脚那一段和圆环相交）就开始沙漏计时；
  可见度低于门槛的点不参与（被身体挡住的看不见的手/脚不会误触）。所以「只用指尖戳进去」「只把脚尖探进去」
  「脚尖还搭在圆圈边上」都算。
  > 「一组结束后」的那两个大圆环仍然是「把**手掌中心**放进圆环中央」的口径（它们本来就是摆明让你放手心的），
  > 「整只脚的中心」也仍然保留 —— 它现在是**报告用**的代表点（🐞 面板与手势圆环用）。
  > 为此 `touchPoints` 会把补出来的外延点（`ghost`）**过滤掉**再取平均：中心不能被外延点往指尖方向拽，
  > 否则那两个大圆环的手感就变了（`tests/test-app.mjs` 钉住了「代表点仍是踝+脚跟+脚尖的均值」）。
- **「只要手和脚有一部分进入就可以开始计时」的最后两块拼图**（用户第三次反馈）：
  > 「感觉目前必须是脚踝和手腕进入才开始 3 秒计时，这个不好，请优化。改为只要手和脚有一部分进入就可以开始 3 秒计时了。」
  改之前「一部分」在代码里其实只有**手腕 / 脚踝**两个候选点真的可用（⑨），判定面又严格等于圆圈（⑩）——
  两件事叠起来，手感就是「必须把踝塞进去」。现在：
  - 手掌 / 脚尖会**按肢体方向补出来**（用肘 / 膝当参考，见 `touchSamples` 里的 `extend()`），
    所以「手腕还在环外、但手掌已经压在圆环上」当场算数，「脚尖搭上圆环」也一样；
  - 判定半径再放宽 12%，手/脚**贴着圆圈外沿**不会白等；
  - 补出来的点只服务这个退出圆环，其余判定一律不受影响。
  `tests/test-app.mjs` 用「真的朝圆环伸过去的一条手臂 / 一条腿」（肩-肘-腕、膝-踝共线）把这两层分别钉住，
  并配了三条反例：1.2 倍半径仍然不算、手腕 / 脚踝本体确实在画出来的半径之外（证明放宽真的起了作用）、
  「再做一次」圆环在 1.06 倍处仍然不算（证明宽容度只给了退出圆环）。
- **脚尖是「估」出来的话，🐞 面板会写明**：那一行会显示成
  「手/脚 **脚·脚趾尖(估算)**(0.07,0.88) 离环心 0.31 环内 整只脚碰到 环内点 1」——
  「靠点在环里 / 靠整只脚碰到 / 脚尖是估算的」三种情况一眼分得清。
- **还加了一行诊断**：打开 🐞 面板，最后几行里会多一条
  **「手/脚 手·食指(0.09,0.85) 离环心 0.42 环内 环内点 2」**（没看到就是「没看到手或脚」）——
  「到底有没有识别到我的手/脚、是哪个部位进去了、差多远」直接看这一行，不用猜。
- **镜像也钉住了**：镜像开关默认是开的，判定跟着镜像走（手放在屏幕上看得到的那一边才算），
  `tests/test-app.mjs` 正反两个方向都测了。
- **只在摄像头开着、而且不在手势菜单里的时候显示**（用户要求）：摄像头没开、或者出错了
  （`camera.active === false`）就不摆 —— 那时候手/脚也识别不到，圆环没有意义；
  手势菜单里也不摆（菜单每一级都有一格「↩ 返回」，见上面的「全手势操作」一节）。
  摄像头一开一关它自己跟着出现/消失（主循环里每帧对齐）。
  摄像头开着时在校准 / 3-2-1 倒计时 / 计数中 / 暂停都一直摆着，不必等一组做完 ——
  这样手上全是汗、离键盘远的时候也能直接退出。
- **动画与「一组结束后」的两个圆环完全同一套**：同样的 `ring-btn / ring-svg / ring-fill` 与 SVG 结构、
  同样的顺时针走满一圈、同样的 `paintRing` 进度逻辑、同样的 **3 秒**（`GESTURE_HOLD_MS`）与同样 300ms 的抖动宽容。
  区别只有：位置固定在**右上角**、手或脚（**任何一部分**）都算、触发后退出这一组（回手势菜单）。
- **贴在画面右上角**（用户要求「把『退出』这个圆环从左下角移到右上角」）：
  右边距 **18px** = HUD 的右边距 18px，上边距 **16px** = HUD 的上边距 16px（`.hud` 的 `padding: 16px 18px`），
  再各自叠加 `safe-area-inset-right` / `-top` —— 所以在刘海屏上它也不会出界。
  **位置只有 `ringCenter('corner', …)` 一处定义**：`layoutCornerRing()` 用它摆画出来的圆环，
  `anyTouchInRing()` / `handInRing()` 用它判手 / 脚在不在环里，所以「看到哪就是判哪」。
  HUD 左栏（**名称那一行胶囊 + 目标 / 圆环 / 计分那一列**）留了
  `max-width: calc(100% - var(--ring-px) - 48px)`，右边界永远停在退出圆环左边缘**往左 30px**；
  名称再长也只是**单行省略**（`text-overflow: ellipsis`），既不会换行把 HUD 撑高，也不会钻到圆环底下。
- **手势菜单右上角那颗「↩ 返回」也走这一套**（用户要求：「把菜单界面中的退出圆环始终放在右上角，
  且各界面退出圆环的位置和大小都保持一致」）：几何由 `exitRingLayout()` 一处给出（同一个 `ringCenter('corner')`、
  同一个 `--ring-px`），摆放也走同一个 `layoutExitRing()` —— 两个界面里这颗圆环**屏幕坐标 / 尺寸逐像素相同**；
  菜单那颗的元素常驻在 `.menu-screen` 之外，所以换屏滑动不会把它带走（`tests/test-app.mjs` 直接比对两处的行内坐标）。
  小屏两条 `--ring-px` 覆盖（720px → 84px、560px → 72px）下的直径由 `#ringSizeProbe` 探针读出来，
  不会退回「按视口宽度套 clamp」那个只在宽屏成立的兜底值。
- **两个圆环永远一样大**：直径共用 CSS 变量 `--ring-px`（`clamp(104px, 10.5vw, 140px)`，小屏另有覆盖）——
  改这一个数两个一起变，所以「各个圆环大小一样」是一条样式约束，不会各写各的（`tests/test-page.mjs` 盯着）。
  > 🐞 顺手修掉一个**让退出圆环看起来小一圈**的真 bug：`showCornerExit()` 原来是**先量尺寸、后显示** ——
  > 元素还在 `display: none` 时 `clientWidth` 是 0，量到的是兜底值，而那个值会被写成**行内 width/height**
  > （行内样式压过 CSS 变量），于是这个圆环一直被钉在比 HUD 进度圆环更小的尺寸上。
  > 现在改成**先显示、再量尺寸**，并且兜底公式也改用**视口宽度**（和 CSS 里的 `vw` 同一个口径），
  > `tests/test-app.mjs` 用「元素藏着时量不到尺寸」的桩把这条回归钉住了。
- **它不用再躲进度条**：判定进度条两侧仍然用 CSS 变量 `--bar-side-space`（= 边距 + 圆环直径 + 12px 间隙）
  给自己收着宽度（这是上一版给左下角圆环留的，留着不影响任何东西）；现在圆环搬到右上角，
  进度条在画面底部居中，两者不会再重叠。屏幕特别窄（≤560px）时进度条整体上移，同样不压别的控件。
- **点一下同样有效**（鼠标 / 触屏），和另外两个圆环一样。
- **「一组结束」的两个大圆环出来时它先收起来**（那儿已经有「退出」了），大圆环收起后又摆回来。
- ⚠️ 判定是**连续停满 3 秒**，这也是它的防误触设计：手/脚只是路过、或者碰到一半又拿开，都会退回 0 不触发。
  如果你的机位让它在你不想退出的动作里误触（比如某个卧姿动作手正好停在那块），告诉我，我给它加一条保护。
- **猫爪指针也跟着手走**（用户要求「在每个运动的窗口里面，如果手掌进入或者靠近类似『退出』这样的圆环，
  则像菜单界面一样出现猫爪」）：运动界面（校准 / 3-2-1 倒计时 / 计数中 / 暂停，以及「一组结束」和右上角
  这两个圆环摆着的时候）里，只要识别到手掌就把它画成一只**猫爪指针**，位置就是圆环判定用的同一份手掌坐标
  （镜像设置一致）；它挂在 `#stage` 下、和手势菜单共用一层（换屏滑动时不跟着动），`pointer-events: none`
  永远不挡点击。大小几轮下来定成**约为圆环直径的 85%**（`calc(var(--ring-px) * 0.85)`，圆环 104~140px →
  猫爪约 88~119px，跟着窗口自动缩放、不写死像素），不透明度 **0.88**、投影柔和 —— 看得清手在哪，
  又不会把圆环整个盖住。

#### 「设置」圆环（退出圆环正下方）与「每组次数 / 秒数」选择层

> 用户要求（原话）：「在每一个运动的页面的右上角『退出』圆环**下方**增加一个『**设置**』圆环，
> 当用户选择之后，在**界面中间出现多个圆环**，让用户选择该运动**每组运动的次数或者秒数**，
> 比如在俯卧撑界面，则选择每组多少次，在平板支撑界面，则选择多少秒。」

- **位置与尺寸都从退出圆环那一份派生**（一处定义，不另写坐标）：`ringCenter('settings')` 的 x 直接取
  `ringCenter('corner')` 的 x，y = 退出环圆心 + **直径 + `SET_RING_GAP_PX`（12px）**；
  `settingsRingLayout()` 把直径 / 半径 / 判定半径 / 图标比例原样复用退出环那一份，`layoutSetRing()` 负责摆。
  视口宽 1280px 时 `--ring-px` = 134px：退出环圆心 y = 83px，设置环圆心 y = 83 + 134 + 12 = **229px**，
  两颗环的 cx 相同 —— 行内 left/top（绘制）与 `anyTouchInRing(samples, 'settings')`（判定）是同一个数。
- **交互和退出环一模一样**：手 / 脚任意一部分进环、停满 `GESTURE_HOLD_MS`（3 秒）就触发，鼠标 / 触摸点它也行；
  蓄力进度、`near` 亮环、环里的秒数、宽容度（`RING_TOUCH_TOL`）全部复用同一套。触发之后要**先离开圆环**才会
  重新武装，否则手一直停在环里会每 3 秒开 / 关一次。
- **圈里是齿轮线条图标**（`src/icons.js` 的 `ui:settings`，和主页那颗 ⚙️ 同一个形状），**不是 emoji**；
  文字含义在 `data-i18n-title` / `aria-label` 上（`ui.gestureSet`：设置 / Settings）。
- **点开之后，屏幕中间出现一圈圆环**：计数类动作（俯卧撑 / 深蹲…）选**每组次数**（`SET_REP_CHOICES` =
  5 / 8 / 10 / 12 / 15 / 20），计时类动作（平板支撑）选**每组秒数**（`SET_SEC_CHOICES` = 15 / 20 / 30 / 45 / 60 / 90）。
  每颗环里是「大号数字 + 小号单位（次 / 秒）」，**当前值高亮**（`is-current`：品牌青 + 一圈内描边）。
  两份列表都是**一处定义**：界面渲染、键盘顺序与测试都从这两个常量读。
- **版式按舞台算**（纯函数 `setChooserLayout()`，绘制与判定共用同一份坐标）：大屏排成一整排
  （1280×720 → 6 颗一行、每颗 Ø132px），宽度不够就退成 **3×2**（560×320 → 3 列 2 行、每颗 Ø92px），
  再窄退成 2 列；每颗直径 ≥ **44px**（触屏热区底线），上下留白 54~64px / 68~84px 留给标题和关闭按钮，
  所以圆环不会钻到字或按钮底下。
- **选中就写进这个动作自己那一份**：计数类 → `settings.targets[id]`，限时计数 → `settings.seconds[id]`
  —— 走的就是「运动设定」弹窗那个 `setTarget()`，**没有新造存储**。计时类动作的「每组秒数」同样落在
  `settings.targets[id]`（那是这个动作的**目标值**；`settings.seconds` 只给限时计数用）。
  改的正是当前动作时，HUD 左上角的目标文案（「20 次」/「45 秒」）立刻跟着变，`saveSettings()` 也已经持久化。
- **三种关闭方式**：点空白处（遮罩）/ 按 `Esc` / **再点一次设置环**（toggle）。选择层的 z-index 比右上角那两颗
  圆环低一层，所以「再点一次」任何时候都点得到；猫爪层仍在最上面，手在哪照样看得见。
- **键盘与触屏都能用**：每颗圆环都是真 `<button>`（能 Tab 过去、回车 / 空格选中），数字键 `1`~`9` 直接选第几个；
  关闭按钮与遮罩都是 ≥44px 的热区。
- **选完不会开始 / 结束这一组**：只改目标；选择层开着时的 `Esc` 只关它自己，不会顺手结束这一组。

## 📐 关键帧判据与判分（运动设定弹窗里的第二步）

在「运动设定」**第二步**（先在第一步选好动作之后）只列一组 —— **🎬 关键帧与判分**：把画面上那条进度条的**每一格**逐格列出来，
格子里的**线条图标**、序号 + 短标签、**这一格的判定标准**（就是进度条格子上那条判据）、
以及**这一格能拿多少分**；最后一格上还会打一个绿色徽标标出**「计次那一刻」**
（计时类动作是**「开始计时」**）。底下那行小结会写「共 N 格 …… 每格分数加起来 + 整轮满分 = 每轮 X 分」。

**判据完全挂在关键帧上**：弹窗里已经没有单独的「计次判据（做到什么程度算一次）」与「姿势要求」两组，
只有关键帧 + 下面的「姿态提醒」（只出声纠正、不吃次数的那几条）。与某一格绑定的补充判据会写在这一格下面：

- **第一格**（进入动作的姿势）：其余姿势要求（躯干、离地高度…）；
- **「计次」那一格**：深度到位线、以及「更浅只算晃了一下」的那条线；
- **最后一格**（计次那一刻 / 开始计时）：一轮最短用时、计时类的起算时间与容错宽限期。

以深蹲为例（数值就是代码里的常量，和画面上的格子一一对应）：

| 关键帧 | 判定标准 | 判分 |
|---|---|---|
| ① 站姿 | 髋比膝高 ≥ 0.86×小腿长 | +4 |
| ② 开始 | 髋比膝高 ≤ 0.78×小腿长 | +6 |
| ③ 计次 | 髋比膝高 ≤ 0.62×小腿长 | +21（下沉 7 + 蹲到水平 14） |
| ④ 回位 · **计次那一刻** | 髋比膝高 ≥ 0.86×小腿长 | +8 + 整轮满分 6 |

以箭步蹲为例（分组只剩关键帧 + 姿态提醒）：

| 关键帧 / 分组 | 判定标准 | 判分 |
|---|---|---|
| ① 站姿 | 双腿伸直角 ≥ 145° | +4 |
| ② 开始 | 前膝屈角 ≤ 146° | +11 |
| ③ 计次 | 前膝屈角 ≤ 138° | +11 |
| ④ 双腿 | 较直那条腿的膝角 ≤ 146° | +14 |
| ⑤ 回位 · **计次那一刻** | 从本轮最弯处回升 65%，或比最弯处高 8° 以上 | +8 + 整轮满分 6 |
| 姿态提醒 | 后膝接近地面（只出声，不吃次数） | 后膝离地高度 ≤ 0.66×小腿长 |

> 每一格下面还会带上它自己的补充判据，例如深蹲第一格写「还要满足：请正对摄像头、躯干倾角 ≤ 20°」，
> 计次格写「深度到位（拿满深度分）：髋比膝高 ≤ 0.4×小腿长 · 比这还浅只算晃了一下：> 0.74×小腿长」，
> 最后一格写「一轮最短：≥ 0.48 秒」；箭步蹲的第一格写「请侧对摄像头、躯干倾角 ≤ 32°」，
> 姿态提醒里还有「膝盖不要内扣」。

> 关键帧那一组和画面上的进度条**用的是同一份数据**（`app.js` 的 `criteriaModel()`：
> 同一批格子、同一批图标、同一份「得分分配到关键帧」的表 `stagePoints()`），
> 所以弹窗里写的「第几格要什么、拿多少分」和你在画面上看到的永远一致，
> `tests/test-app.mjs` 会逐条核对格数、图标、分数与总分。

> **这些数字不是另写的一份说明，而是从识别器真正使用的常量里取出来的**（见 `src/specs.js`）：
> 手写识别器读 `SQUAT / LUNGE / PUSHUP / BRIDGE / PLANK` 的阈值表，通用引擎读该动作在
> `catalog.js` 里的 `up / down` 与 `enter / bottom / loose / ignore` 进度，姿势门控读
> `engines.js` 的 `GATE_LIMITS`（同一张表也用于判定），计时类读 `HOLD_PRIME_MS / HOLD_GRACE_MS`。
> 改了阈值，弹窗里的数字自动跟着变，不会出现「界面说的和实际判的不一样」。
> `tests/test-specs.mjs` 会在每次测试时把这些数字**喂回识别器本体**验证：

## 怎么用（机位很重要）

**正面机位：自重深蹲、相扑深蹲、深蹲跳、开合跳、波比跳；其余动作都是侧对镜头。**
动作页的「动作要领」第一行会写明这个动作该怎么站（每张卡片上也标了判定依据）。

- **正面动作**（自重深蹲 / 相扑深蹲 / 深蹲跳 / 开合跳 / 波比跳）：正对摄像头。深度用「髋比膝高多少」判断，
  这个量在正视图里不被压缩；而且正对镜头才能看清膝盖有没有内扣、左右是否对称。

- 与摄像头相距 **2~3 米**，让**全身入镜**（头顶到脚都在画面里）；
- **箭步蹲 / 向后箭步蹲**：侧对镜头站立，画面里能同时看到脚踝、膝盖、髋、肩；
- **俯卧撑 / 平板支撑 / 登山者**：人趴的方向与镜头垂直，手和脚都在画面内；
- **臀桥 / 卷腹 / 仰卧抬腿 / 死虫式**：躺姿，侧对镜头，能同时看到肩、髋、膝、踝；
- **拉伸**：站立体前屈侧对镜头站直；坐姿体前屈坐在地上侧对镜头；
- 光线均匀、背景别太乱，穿贴身一点的衣服识别更稳。
- **没有声音？** ① 看标签页有没有被静音（标签上的小喇叭图标）② 打开设置点一次「🔊 语音报数」，会立刻试播一句 ③ 打开「🐞 识别指标」，最后一行的「声音」应显示 running 且语音包数大于 0。

**注意流程是：选动作 → 进入虚线轮廓 → 全身识别完成（虚线轮廓消失）→ 自动 3-2-1 倒计时 → 开始计数；
一组结束后回到校准，再点「开始训练」（或按空格）开始下一组。**
校准阶段只做就位判断，不会计数也不会得分。

> **全屏（`F`，或视频框右下角的 ⛶）放大的是「视频框」本身**，不是整个 HTML 页面 —— 侧栏、要领清单、成绩卡不会被一起放大。
> **做完一个动作「退出」回主页时会自动退出全屏**（用户要求）：从全屏里点「退出」圆环、点顶栏 🏠、
> 按 `H`、或者用浏览器后退回主页，都会先把全屏收掉，主页直接就是正常排版，不会顶着一个放大的页面、
> 也不用再按一次 Esc。**只是「结束本组」而人还留在动作页时不会动全屏**（还要接着练下一组）。

**快捷键**：`1`~`9` 快速切动作 · `H` 主页 · `G` 设置 · `空格` 开始/暂停 · `R` 重置计数 · `Esc` 结束本组 · `M` 镜像 · `S` 火柴人 · `F` 视频框全屏

## 计分规则

界面右侧有一张**要领清单**，做对一步就立刻打勾、加分、响铃，当前该做哪一步会高亮。
**整轮要领全部完成**还有额外的满分奖励；计时类动作**每保持 1 秒再加 1 分**。

### 深蹲（每轮满分 45 分）

深蹲用**正面**机位，深度用「髋比膝高多少 / 小腿长」判断（站直 ≈ 1.0，蹲到大腿水平 ≈ 0）：

| 要领步骤 | 判定条件 | 分值 |
|---|---|---|
| ① 正对摄像头站好，全身入镜、身体直立 | 正面视角 + 全身可见 + 身体竖直 + 髋明显高于膝（比值 >0.86） | +4 |
| ② 屈膝下蹲，髋部向下沉 | 髋膝高度差比值 ≤0.72（大腿离水平约 46°） | +6 |
| ③ 双膝顺着脚尖方向屈曲下沉 | 比值 ≤0.50（约 30°） | +7 |

> **⚠️ 修过一个大 bug：向后箭步蹲「右腿向后箭步时不计次」。**
>
> 用户反馈：「关于向后箭步蹲……如果我**右腿向后弯曲箭步**的时候是没有计数的。」
> 用他本人打开的调试日志（`logs/pose-lungeBack-*.jsonl`，1641 帧真实关键点）复现出来了 ——
> 是**两个原因叠在一起**：
>
> 1. **门控用了一条依赖地面线的条件**。向后箭步蹲的站立门控是 `stand`，其中一条是
>    「**膝离地 ≥0.28 倍躯干长**」；可向后箭步蹲**做到底时后膝就是贴地的**：
>    日志里那一轮最深 68°，而**膝离地读数掉到 0.004**，最深的 6 帧连续不过门控。

>    表现就是「有时计得上、有时一整轮白做」。
> 2. **门控掉一帧就把这一轮作废**。引擎原来**一帧**不过门控就把 `peak / repStartAt` 清零：
>    深度白做；站起来时被当成新一轮，用时只剩几百毫秒 → 又判成「太快了」，

>
> - 向后箭步蹲的门控换成 **`standUpright`**：只看「**躯干竖直 + 肩高于髋**」，与地面线无关
>   （勾腿跳用的同一套，见上面 `standUpright` 的说明）；
> - 引擎加了 **400ms 的门控宽限**（`GATE_GRACE_MS`）：门控掉不超过 400ms 时只是**不推进**，
>   不把 `peak` 和计时清零；掉得更久才认为真的不在这个姿势里，按老规矩作废。
>   这条对**所有用屈伸引擎的动作**都生效（深蹲 / 相扑深蹲 / 深蹲跳 / 开合跳…），
>   顺带挡住 MediaPipe 单帧跳变造成的假「离开姿势」。
>
> 拿他那一组日志重放验证（同一份真实帧，只换门控）：用户实际得到的是
> **5 次 + 3 次「太快了」被拒**，修复后 **8 次全计上**（用时 1.4~1.8 秒，不再被误判成几百毫秒）；
> 只有最后那一轮真实只弯到 133° 的浅动作仍然提示「再多做一点」—— 该拦的照样拦得住。
> 回归夹具是 `tests/fixtures/lungeBack-right-leg-back.json`（34 帧真实关键点），换回旧门控就红。

### 俯卧撑（每轮满分 40 分）

> **用户要求：「俯卧撑的标准太复杂了，无法计次，请大幅度简化计次标准。」**

改写之前它确实太复杂了：一个手写识别器，同时看**肘角**和**肩膀下沉量**两个指标、8 条阈值、
还有「顶位基准 / 开始下沉 / 计数线 / 回到顶位 / 肩膀第二路证据 / 抖动驻留 / 最短一轮」一整套状态机 ——
弹窗里一次列 8 个数，规则越加越细，实际用起来反而「做了好几个一个都没计上」。

现在**只剩一个指标：肘角**，四条线全落在它上面，而且都跟着**你自己撑得最直的那个角度**走
（引擎取最近 1.5 秒里你实际到过的最大肘角当基准，不高于 170°）：

| 环节 | 判据（以「你自己的顶位」为 100%） | 默认顶位 170° 时 |
|---|---|---|
| 回到起始位（上一轮的收尾、下一轮的前提） | 回到顶位 **12%** 以内 | 肘角 ≥ **161°** |
| 开始下沉 | 比顶位弯 **15%** | 肘角 ≤ **159°** |
| 只晃了一下（不计次、也不出声） | 没到 **20%** | 肘角 > **155°** |
| **计次线** | 比顶位弯 **30%** | 肘角 ≤ **148°** |
| 满分深度（只影响分数与提醒） | 比顶位弯 **75%** | 肘角 ≤ **114°** |

> **⚠️ 修过一个大 bug：俯卧撑弹出「还没进入这个动作的姿势」之后，就再也不计数了。**
>
> 用户反馈：「俯卧撑运动中，一旦出现『还没进入这个动作的姿势』这样的提示，后续无论怎样做俯卧撑都不计数了。」
> 查下来是门控的问题：旧的俯撑门控（`prone`）里有两条**以校准地面线为基准**的条件 ——
> 「肩离地 ≥0.10×躯干长」和「**手离地 ≤0.95**」。地面线一旦偏掉
> （校准时站的位置和做动作时不一样、摄像头被碰过、换了个地方躺下），这两条读数就整体平移：
> 地面线偏低 0.3 时「手离地」实测读到 **1.07 > 0.95** —— **姿势再标准也永远过不了门控**，
> 识别器恒 `active = false`，于是一次都不计数（探针复现过）。
> 这和当初**站立门控**踩的是同一个坑（「我明明站好了，它却总说我没站好」，见上面 `standUpright` 的说明）。
>
> 现在俯卧撑 / 登山者改用 `proneUpright`：只看两个**身体自己跟自己比**的量，与地面线、机位距离都无关 ——
>
> | 门控条件 | 含义 | 站着的人 |
> |---|---|---|
> | 躯干倾角 ≥ **32°** | 躯干在画面里明显接近水平 | 站直只有几度 → 被拦住 |
> | 手举过肩的高度 ≤ **0.45×躯干长** | 手没有举到肩上方（撑地 / 趴着的姿态） | 举手过头顶是开合跳那类 → 被拦住 |
>
> 回归测试（`tests/test-engines.mjs` 的 `[5a]`）把这件事钉住了：把校准地面线人为偏 **±0.3 / ±0.5** 之后，
> 5 次标准俯卧撑仍然要计到 ≥4 次 —— **用旧门控时这一个用例实测是 0 次**，正好复现用户的症状。
> 另外 🐞 面板新增一行「**姿势门控**」，把门控真正在看的每个量连同它的线和过没过都摆出来
> （例如 `torsoIncl 63(>=32)✓ armRaised -1.09(<=0.45)✓`），以后再遇到「总说我没进入姿势」看一眼就知道卡在哪一条。

- **一轮 = 「沉下去过计次线 → 推回起始位」**：计次发生在**回到起始位那一帧**，
  所以数出来的一定是完整的一下一上，半程、抖动、停在半路都不会算进去。
- **手臂伸不直的人也照样计次**：线全都相对「你自己的顶位」算 —— 顶位只有 150° 的人，
  计次线就是 134°（而不是写死的 148°），不会出现「线比他的顶位还低 → 永远计不上」。
- **实测边界（钉在测试里）**：肘只压到 **145°** 的浅俯卧撑每次都计上；只到 **148°**（没过线）一次都不计；
  肘角读数只有 150° / 146° / 142° / 138° 的人连续 5 次都计到 5 次。
- **抖动**：单帧毛刺（33ms 掉进计次线又弹回来）会被「一次一轮至少 0.35 秒」拦下来，记成「太快」而不是白计一次；
  只晃一下（没到 20%）**既不计次也不出声**；真的做了但没过线会提示「幅度再大一点」。
- **宽松模式一直是唯一一档**（用户要求取消严格模式）：深度不够照样计次，只是质量分打折、
  并出声纠正姿势（塌腰 / 撅臀 / 身体不成一条线只提醒，不拦计数）。

| 要领步骤 | 判定条件 | 分值 |
|---|---|---|
| ① 仰卧屈膝，双脚与髋同宽踩实 | 仰卧屈膝姿（肩贴地、膝离地）+ 髋角还没顶起来 | +5 |
| ② 收紧臀部，把髋部向上顶起 | 髋角 ≥ 155°（离开躺平） | +6 |
| ③ **顶到肩-髋-膝一条直线（满分步）** | **髋角 ≥ 170°**（≈180°）**且 膝角 55°~130°**（≈90°） | **+14** |
| ④ 臀部有控制地落回躺平 | 髋角回到**你自己躺平的读数 +12°** 以内（需先顶起过） | +8 |
| 🎁 整轮要领全过 | 上面 4 步同一轮内全部达成 | +6 |

**顶点判据现在是两个关节角的「且」，高度彻底退出了判定：**

| 条件 | 判据 | 为什么 |
|---|---|---|
| 髋角（肩-髋-膝） | ≥ **170°**（用户要的 180°，留了余量） | 「顶到位」的姿势本身就是躯干与大腿连成一条直线；躺平屈膝时约 135°~145° |
| 膝角 | **55°~130°**（用户：「90 度左右，但可以放更宽一些」） | 必须是**屈着膝**顶起来的 —— 否则「躺着把腿伸直、靠腰把身体翘起来」也会读到 180°，那就不是臀桥了。75°~110°（≈90°）质量分最高 |

- **为什么去掉高度**：`hipRise`（髋比肩高多少）是**以校准地面线为基准**的量 ——
  身高腿长、肩离地多少、镜头高低都会影响它，有人顶到极限也到不了 0.35 倍躯干长，
  于是「明明顶到位了却不计次」。角度是**身体自己跟自己比**，与地面线、机位距离都无关。
- **判定线跟着你自己躺平的读数走**：识别器记「你这一组躺平时髋角的最低值」（躺着那几帧的最小值），
  `顶点线 = 你的躺平读数 + 26°`（夹在 **170°~176°** 之间）、`落回线 = 你的躺平读数 + 12°`。
  所以躺平读数偏高的人（比如 150°）也够得到顶点线，不会出现「永远顶不到」。
- **计次发生在「从顶点落回躺平」那一刻** —— 也就是进度条最后一格「落回仰卧」点亮的同一刻，
  整条 3 格链（屈腿仰卧 → 曲腿腰臀顶起 → 落回屈腿仰卧）走完并计一次。
  一整轮少于 0.42 秒只当抖动，不计数、只提示放慢一点。
- **两种失败都给具体提示**：只顶到一半（髋角 160° 上下）→ 「臀部再顶高一点」；
  顶起来了但腿伸直了（膝角 >130°）→ 「膝盖要保持弯曲（约 90°）」。
- **画面上标的两个数就是这两个判据**：侧对镜头时会标「髋 xx°」（肩-髋-膝）和「膝 xx°」，
  🐞 面板也有「髋角(顶点线) / 膝角(窗口) / 躺平基准」三行，对着调很快。
- **实测（合成骨架 + 真实管线）**：标准臀桥（髋角 180°、膝角 90°）5 轮计 5 次；
  用户那种「升幅很小但成一条直线」的臀桥也计 5 次（这正是旧高度判据卡住的情形）；
  半程（髋角只到 160°）一次都不计；腿伸直顶到 180°（膝角 145°）一次都不计；仰卧不动 0 次。


### 平板支撑（一次 70 分 + 每秒 1 分）

| 要领步骤 | 判定条件 | 分值 |
|---|---|---|
| ① 小臂在肩下撑地，把身体撑起来 | **肩关节角（髋-肩-肘）45°~135°**，或 肩离地 + 手贴地 | +8 |
| ② 头、背、髋、脚踝成一条直线 | 身体直线角 ≥148° + 不塌腰不撅臀 | +12 |
| ③ 稳定保持 3 秒 | 保持满 3 秒 | +10 |
| ④ 稳定保持 10 秒 | 保持满 10 秒 | +15 |
| ⑤ 稳定保持 30 秒 | 保持满 30 秒 | +25 |
| ⏱ 每保持 1 秒 | 姿势有效期间 | +1/秒 |

> **用户反馈「平板支撑没有计时，可能是规则『手离地高度 ≤ 0.55×躯干长』太严了」—— 完全正确，已经改掉。**
>
> 复现：**躺得再标准的平板，只要校准地面线比身体低**（在床上/沙发上做、或者机位偏一点），
> `手离地高度` 就量成 **0.68 > 0.55** → 屏幕上一直提示「手掌/小臂要贴在地面上」、**一秒都不计时**。
> 用户同时给出了他心里的判据：「**主要是判断关节角度**：肘 90° 左右、**肩 90° 左右**、
> 髋膝都在 180 左右、躯干倾角 80° 左右，手离地高度不要太严」—— 实测标准小臂平板正好是
> **躯干 78° / 肩 78° / 肘 90° / 髋 180° / 膝 180°**，和他说的完全一致。
>
> 所以「撑住了没有」现在改成**两路证据取「或」**，主路是**角度**（不依赖地面线）：
>
> | 证据 | 判据 | 实测 |
> |---|---|---|
> | **肩关节角**（新指标 `shoulderAngle` = 髋-肩-肘） | **落在 45°~135°** | 小臂平板 ≈78°、直臂平板 ≈90°、**趴着休息（手臂贴身）≈10°**、站着 ≈25° |
> | 老的地面线判据（替代路径） | 肩离地 ≥0.10 **且** 手/小臂离地 ≤0.55 | 保留成备选，原来能过的现在照样过 |
>
> - 仍然必须「身体接近水平（躯干倾角 ≥38°）」；站着（4°）两条证据也都不成立，照样不计时。
> - 塌腰、撅臀、身体不够直、膝盖偏低、肘角读数模糊仍然只是**语音纠正 + 质量分打折**，不打断计时。
> - **画面上的标注也跟着判据走**：平板支撑现在标 **「肩 xx°」**（髋-肩-肘，就是决定计时跑不跑的那个角）、
>   **「肘 xx°」**（小臂撑 ≈90° / 直臂撑 ≈175°）、「髋 xx°」和「躯干 xx°」—— 用户说的四个数都在屏幕上。
> - 进度条两格：**① 撑起（躯干倾角 ≥38°）→ ② 肩撑住（肩关节角 45°~135°，开始计时）**。
> - 计分方案里那条 +8 分的「撑起来」也换成同一套口径（角度优先，老判据兜底），不会再出现
>   「识别器说撑住了、得分项却因为手离地不够近而不给分」这种不一致。

### 通用「族」计分方案

除了上面 5 个手写方案，其余动作共用**族方案**（同一类的动作判定逻辑一致，只是阈值不同）：

| 族方案 | 用在哪类动作 | 步骤构成 |
|---|---|---|
| 站姿屈伸 | 相扑深蹲、向后箭步蹲 | 站好 → 屈膝下沉 → 做到目标幅度 → 蹬地还原 |
| 仰卧抬起 | 反向卷腹、仰卧抬腿 | 躺好 → 启动发力 → 抬到位 → 控制着放回 |
| 左右交替 | 死虫式、登山者 | 摆好姿势 → 第一次收/伸 → 换另一侧 → 保持节奏（**死虫式的判据与关键帧单独做过**，见下） |
| 站立左右交替 | 勾腿跳 | 站立 → 勾腿 → 勾另一条腿 → 保持节奏 |
| 多段动作 | 波比跳 | 站好 → 下蹲撑地 → 完成中段 → 起身收尾 |
| 跳跃类 | 深蹲跳 | 站好 → 屈膝蓄力 → **双脚离地** → 屈膝落地 |
| 开合跳 | 开合跳 | 双脚并拢站好 → 打开、双手上举 → 开到最大 → 收回并拢 |
| 计时（拉伸） | 站立体前屈、坐姿体前屈 | 进入拉伸姿势 → 放松呼吸 → 保持 10 / 20 秒 |

> 另外还留着一套**通用的「计时（姿势）」方案**（`holdPose` 计划：姿势到位 → 身体成一条线 → 坚持 3 / 10 / 30 秒）——
> 它原本是侧平板支撑在用，动作删掉之后目录里已经没有动作走这条路了，但 `kind: 'hold'` 的**默认** plan 仍是它，
> 所以代码与测试都留着（以后加计时动作不用再写一套）；`tests/test-detectors.mjs` / `tests/test-engines.mjs`
> 用手工构造的动作 meta 把这条通用路径走通，不让它烂掉。

计时类族方案同样是**每保持 1 秒 +1 分**，姿势垮掉超过 1.2 秒会暂停计时并语音提醒。

### 死虫式（判据按用户反馈重做过）

> **用户反馈：「死虫式的关键帧判别标准我感觉都不对」** —— 查下来确实三处都不对，
> 因为原来直接套了「左右交替」族的通用判据（**只看一侧的膝角 ≥150°**）：
>
> | 原来错在哪 | 为什么会错 |
> |---|---|
> | ① 错法也能计上 | 只把小腿踢直、**大腿还竖在桌面位（脚朝天）** 也会满足「膝角 ≥150°」，可那只是屈伸膝，不是死虫式 |
> | ② 真做了却计不上 | 腿真的伸出去、但膝盖差几度没绷直（腿后侧紧的人很常见）就不计次 |
> | ③ 两条腿一起伸也计上 | 引擎在「两条腿同帧进线」时按更深的一侧认一次 —— 而死虫式的要点恰恰是**一次只伸一条腿** |
>
> **现在的判据**（三格关键帧）：
>
> | 关键帧 | 判据 | 参考值 |
> |---|---|---|
> | ① 仰卧（桌面位） | 仰卧（躯干倾角 ≥36° + 肩离地 ≤0.6×躯干长）；图标画的是**双腿屈膝 90° + 双臂朝天**的桌面位 | 大腿竖直、膝屈 90° |
> | ② 伸腿（计次线） | **腿伸出去的程度 ≥132°** **且** **另一条腿留在桌面位 ≤120°** | 桌面位 ≈90°、伸出去贴地 ≈170~180° |
> | ③ 换腿（计次那一刻） | 另一条腿也伸出去（≥132° 且这一侧收回 ≤112°）；换边成功那一刻计一次 | 两次之间至少 0.5 秒 |
>
> - **「腿伸出去的程度」是个新指标 `legOut` = 膝角与髋角里更小的那个**（见 `src/metrics.js`）。
>   死虫式要的是「膝盖接近伸直」**且**「大腿从桌面位向地面方向展开」，两个都到位才算伸出去：
>   只看膝角会放进「脚朝天」，只看髋角会放进「腿放下了但膝盖还屈着」，取小值正好把两种都挡掉。
> - **另一条腿必须留在桌面位**（引擎的 `params.otherHold`）：这是计次的必要条件，写在同一格判据里
>   （弹窗里显示成「… **且** 另一条腿的程度 ≤120°」）。两条腿一起伸出去不再白记一次。
> - **换边那一瞬间不会丢次数**：刚伸完的那条腿大约 200~400ms 才回到桌面位，而另一条腿已经开始伸 ——
>   上升沿正好落在「另一条腿还没到位」的那几帧。所以识别器会把这次伸腿**挂起来**，
>   等另一条腿真的回到桌面位、并且这一侧还伸着的时候补记一次（挂起超过 1.2 秒才判定是「两条腿一起动」并出声纠正）。
>   修好前：换边 4 次只计 1 次；修好后：连续快换 6 次计到 6 次（`tests/test-engines.mjs` 守着）。
> - **关键帧的名字与图标也换了**：短标签「伸腿 / 换腿」（不再是通用的「发力 / 换边」），
>   图标画成**仰卧**：第一格双腿屈膝的桌面位、第二格近侧腿伸出去（远侧腿屈着）、第三格反过来（远侧腿伸出去 + 向下箭头）。
>   以前这三格落到通用分支被画成**脸朝下的俯卧**图（那是登山者的样子），还带一个「膝角」数字，怎么看都不对。
> - **判据里的方向也修了**：交替类那条补充说明以前把方向写死成「≤」，于是死虫式的弹窗把计次线说成「≤150°」—— 正好说反。
>   现在按 `cmp` 生成（死虫式「≥132°/收回 ≤112°」、勾腿跳「≤126°/回到 ≥132°」）。
> - 🐞 面板会给出一行「两侧读数」（就是上面那个 `legOut`）和一行「另一条腿要求 ≤120」，
>   对不上时可以直接看到卡在哪一条上。

### 卷腹（判据按用户给的模型重做：屈膝躺下 → 卷起来）

> **用户给的模型**（原话）：「初始关键帧就是**屈膝躺下**，那么**躯干倾角应该是差不多 90 度**，
> 膝关节弯曲，应该也在 **90 度或者更小**。真正计次的关键帧，和初始关键帧的变化，应该是
> **躯干倾角变小了**，与此同时，**肩关节到髋关节的长度**因为卷腹而变小，可能只有初始关键帧长度的
> **70% 左右**。当然，**头部离地**也是一个关键指标。请根据我的描述优化卷腹这个动作的关键帧，让计数更为流畅。」

**为什么必须重做**：卷腹原来是通用屈伸引擎按 `shoulderClear`（肩离地高度）判的，有两个坑 ——
① 它**依赖校准地面线**（床上/沙发上做、机位偏一点，地面线就落在身体下面，读数整体虚高）；
② 它除以 `torsoLen`，而 `torsoLen` 就是「肩-髋距离」**本身**：卷腹时这个距离缩小，
分母跟着变小、读数被放大 —— **越卷越像满分，判据和动作脱钩**。
现在直接判「肩-髋距离相对**躺平时长度**的比例」（就是用户说的那个 70%），分母是自校准的，与机位无关。

| 关键帧 | 判据 | 参考值 |
|---|---|---|
| ① 屈膝躺下（起始姿势） | 躯干倾角 ≥62° **且** 膝角 25°~118° | 躺平 ≈90°、屈膝 ≈90° |
| ② 卷起来（躯干倾角变小） | 比**自己躺平的基线**小 ≥13°（基线自校准，不是固定角度） | 卷到位 ≈65°~75° |
| ③ 卷到位（**计次那一刻**） | 肩-髋距 ≤**0.80×躺平时**（用户观察 ≈70%，留了余量）**或** 头离地 ≥0.16×躯干长 | 缩到 ≈0.70× |

- **三条证据都自校准，所以和体型、离镜头远近、机位都无关**：躺平基线 = 躯干倾角 ≥68° 的那几帧取最大值
  （缓慢衰减以跟上机位变化）；肩-髋距基线 = 「还没卷起来的那几帧」里的最大值；头离地用**差值**
  （抬头高度 − 躺平时的头高）而不是「离地面线的绝对高度」—— 绝对高度在躺着时也会读到一大截。
- **「让计数更流畅」的四处设计**：
  1. **在卷到位的最高点立刻计次**（和俯卧撑「在最低点计次」同一个思路）：报数、音效、计数跳动都在那一刻，
     不用等躺回去才结算；
  2. 三条线都留了余量（用户观察 70%，计次线取 **80%**；倾角变化取 **13°**），幅度小一点、慢一点都能计上；
  3. 抖动过滤只滤掉「比人能做到的还快」的上下抖（一轮 <0.32 秒），**不因为慢而扣次数**；
  4. 回位判定用「倾角回到基线附近 **且** 三条证据合起来的进度掉回 0.30 以下」，
     而不是单看「肩-髋距回到 94%」—— 幅度小的人躺平时也回不满那条线，只盯它就会永远停在「已计次」状态、
     后面几次一次都计不上（这正是「计数不流畅」最常见的成因）。
- **进度条三格**：**躺下（屈膝躺下）→ 卷起（倾角变小）→ 卷到位（计次那一刻）**，
  分数 12 / 7 / 14 + 满轮 6 = 每轮 39 分；「卷起」那一格用的是识别器自己的**动态线**（躺平基线 −13°），
  所以它会跟着你躺平的角度走。
- **画面标注**：在原来「髋 / 躯干倾角」的基础上改成标 **「膝 xx°」**（屈膝有没有到位）和
  **「头 x.xx」**（头比躺平时抬起了多少，就是判据里那个数）—— 判据是什么数，画面上就标什么数。
- **🐞 面板**给出三行：`躯干倾角(当前/基线)`、`肩-髋距(当前/线)`、`头离地(当前/线)`，
  对不上时一眼看出来是「没卷够」还是「没躺平」。
- 🐞 顺手修掉两个**探针查出来的真 bug**（都写在 `CrunchDetector` 的注释里）：
  > ① **一轮计两次**：原来只用「起始姿势」那一条判「在不在动作里」，而卷起来之后躯干倾角会掉到 62° 以下，
  > 于是被当成「离开起始姿势」→ 相位被重置 → 手一放下又满足计次线。现在分成
  > 「**进门**（严格：倾角 ≥62° + 屈膝）」与「**还在这套动作里**（宽松：倾角 ≥35°、膝角 ≤140°）」两条 ——
  > 只有真的坐起来 / 站起来 / 腿伸直才算离开（探针里 4 轮曾计了 8 次，现在 4 轮正好 4 次）。
  > ② **头离地读成绝对高度**：用「离校准地面线多高」时，躺着也会读到 0.5×躯干长（地面线来自脚踝），
  > 判据形同虚设。改成**差值**之后，躺着是 0、抬头才有数（把机位/地面的系统性偏差全部抵消）。

### 坐姿体前屈（两格关键帧：坐好 → 前折到位）

> **用户反馈：「目前的关键帧判断有问题，实际没有计时」**，同时把运动学写清楚了：
> 「初始关键帧其实就是侧面向镜头坐好，此刻**髋角度约 90°、躯干角度约为 0°**。
> 当身体前屈的时候，**躯干角度和髋角度相加之和应该始终在 90° 左右**。
> 当身体前倾、**躯干角度在 30 左右**基本也就到位、可以开始计时了。」

查下来原来那两条判据都靠不住：一条是 `髋离地 ≤0.9×躯干长`（**依赖校准地面线** ——
床上/沙发上做、或者机位偏一点，地面线比身体低，坐得再标准也读到 1.0 以上，**一秒都不计时**），
另一条是 `躯干倾角 ≥40°`（比用户说的 30° 更严）。现在全部换成**不看地面线的角度判据**，并按用户描述分成**两格关键帧**：

| 关键帧 | 判据 | 参考值（侧对镜头） |
|---|---|---|
| ① 坐好（起始姿势，**认到一次就常亮**） | 躯干倾角 ≤25° **且** 髋角在 70°~115° **且** 膝角 ≥130° **且** 髋不比膝高（≤0.4×小腿长） | 躯干 ≈0°、髋 ≈90°、双腿伸直放平 |
| ② 前折到位（**开始计时那一刻**） | 躯干倾角 ≥28° **且** **躯干角 + 髋角 在 60°~125°** **且** 膝角 ≥125° **且** 髋仍不比膝高 | 躯干 ≈30° 时髋 ≈60°，两数之和 ≈90° |

- **「躯干角 + 髋角 ≈ 90°」是用户给的恒等式，成了一个新指标 `foldSum`**（见 `src/metrics.js`）：
  坐姿前屈时躯干与大腿的夹角（髋角）= 90° − 躯干倾角，所以两者之和始终在 90° 附近。
  这条同时把**站立前折（≈180°）**和**躺着（≥180°）**排除掉 —— 站着做、躺着做都进不来。
- **阈值 28° 而不是 30°**：用户说「躯干角度在 30 左右基本也就到位」，实测折到位的读数会抖到 29.7°，
  所以留 **2° 抖动余量**取下限 28°（这是刻意放宽，不是笔误）。
- **第一格是「锁存」的**（识别器的 `startSeen`）：坐好被认到一次之后就一直亮着，
  身体前折不会把它取消 —— 这一格问的是「你坐好了没有」，不是「你要一直坐直」。
  所以它不能和别的动作共用那条「第一格 = 当前这一帧的姿势」的通用写法（`specs.js` 里单独一条分支）。
- **没坐好就开始折 → 不计时**，屏幕上提示「先坐直坐好」（`cue.notSeated`），
  不会再出现「折了半天进度条不动、也不知道为什么」。
- **计时宽容和别的计时动作一样**：姿势稳定 **0.25 秒**才开始计时，短暂晃动 **1.2 秒**以内不停表。
- **关键帧短标签**是「坐好 / 前折」（进度条悬停与弹窗里都是这两个词），分数 42 + 1/秒（每轮满分 50）。
- **画面标注**：标「髋 xx°」和「躯干 xx°」两个数 —— 它们加起来就是判据里那个「≈90°」。


> **仰卧抬腿怎么判**：判据就是**髋关节的角度**（腿和上身的夹角，单位是度）——
> **躺平、腿伸直贴地 ≈ 180°** → 腿绷直抬起来、角度一路变小 → **抬到腿垂直地面、与上身约 90°** → 放下来回到 ≈ 180°，如此循环。
> `up = 180` 是起始线（跟着你自己躺平的角度自校准：驼背躺不平的人按他自己的最大角度算），`down = 90` 是抬到垂直。
> 进度条四格 = **躺平 → 开始抬起（≤151°）→ 计次（≤105°）→ 放回躺平（≥158°，带一个向下箭头）**。
> 阈值按用户要求都留了宽容，两头都不严格：
> - **抬到髋关节约 90° 就计次**：计数线放在 **105°**（离垂直 15° 以内都算一次），满分深度线 **95°**（基本垂直）；
> - **腿放平就能开始下一次**：回位线放在 **158°** —— 离躺平还有 22° 就算回到起始位，不会因为没完全放平而不结算；
> - 起始格画的是**躺平 + 腿伸直**（不是臀桥/卷腹那种屈膝姿势）；如果膝盖弯着抬（夹角一样能凑到 90°），
>   会语音提醒「腿要绷直」—— **只提醒、不扣次数**。宽容线是**膝盖角度 ≥ 130°**（用户要求「不要太严格，130° 以上都可以接受」）：
>   只有弯过 130° 才出声，弹窗的「姿态提醒」里也列着这条线。
> - 画面上的角度标注写的是**「髋 xx°」**（判据那个数字）—— 和别的动作**同一套叫法**，全应用只有「髋」这一种写法
>   （不再有「腰部角度」「胯」这类特例）。
> - **「躺下没躺下」现在是两条证据取「或」**（用户两轮反馈的结果）：
>   第一轮要求「只保留『肩离地高度 ≤ 0.6×躯干长』，删掉『躯干倾角 ≥ 36°』」；
>   第二轮反馈「**总是进入不了起始姿势**」—— 查下来就是那唯一一条**依赖校准地面线**：
>   在床上/沙发上做、或者机位在脚这一头时，地面线比身体低，躺得再标准也会读到
>   「肩离地 0.69 倍躯干长」而被判成「没躺下」（实测：躯干 90°、髋 180°、膝 178° 的完美躺平被拦住）。
>   现在改成 **躯干在画面里接近水平（≥55°，完全不看地面线）** **或** **肩膀离地面线 ≤0.6 倍躯干长**，
>   任一条成立就算躺下；站立（躯干 10°、肩离地 1.2）两条都不成立，仍旧进不来。
>   弹窗和进度条第一格也如实写成「A **或** B」—— 之前按「还要满足」写成 AND，比实际判得还严。
>   死虫式共用同一套「躺下」判据（同样两条取「或」）。
> - **起始姿势就是躺平**：屏幕上的提示改成这个动作自己的说法「躺到垫子上躺平：身体放平、双腿伸直放松
>   （髋和膝都放平，约 180°）」—— 以前沿用通用那句「仰卧屈膝」，那是臀桥/卷腹的姿势。

> **开合跳怎么判**：正对镜头，用**双腿开合距离**（`legSpread` = **膝间距与踝间距里更大的那个**，单位是躯干长）
> 量「开合」，进度 = (最窄 − 当前) / (最窄 − 最宽)，所以「并拢 → 打开 → 并拢」正好是一轮。
> 判定线跟着**你自己这一组最窄的站距**走（引擎的 `effUp` 自校准），所以本来就站得开的人也照样计次。
>
> 用户反馈「开合跳跳了很多次一次都没计上、卡在第三关键帧」，查下来是判据太严：
> ① **只量膝盖** —— 真人跳开时腿是往外撑的，**脚张得比膝盖大得多**，膝盖读数只有 0.8~0.9，而当时的计数线要求 0.98；
> ② 「最宽」参考值定在 1.5 倍躯干长（≈85cm 膝距），真人的开合跳到不了。
> 现在改成「膝 / 踝取较大值」（取大不算取小，脚出画只看得见膝盖时也照样能用），参考区间收到 **0.30 ~ 1.25**，
> 关键帧按用户要求**只留三格**（快节奏动作，「开始」那一格 0.6 秒就闪过去了、没有信息量）：
> **① 站立 → ② 跳开（计次 ≥ 0.66）→ ③ 收回（≤ 0.54）**，分数相应变成 **4 / 21 / 8 + 满轮 6**（每轮仍是 39 分）；
> 最短一轮从 300ms 放到 **400ms**（真人一轮约 0.6~1.0 秒，更短的只当是抖了一下）。
> 顺带把「收回」那一格的判定放宽到进度 0.45 —— 它必须**在识别器收轮之前**判到，否则永远差一帧、拿不到整轮满分。
>
> 速度快是正常的，只把「上下抖一下」挡掉。关键帧上的图标是**正面火柴人**：
> 并拢（手臂放下）→ 打开（双腿张开、双手举过头顶）→ 开到最大 → 收回并拢（带一个向下的箭头，表示回到起始位）。
> 另外 🐞 识别指标面板现在第一行后面会显示**「🎯 本动作真正在判的那个量 + 进度」**
> （开合跳就是「双腿开合距离 0.83（进度 52%）」），这类「判据不是关节角」的动作出问题时可以直接看数字自查。
> **画面上也直接标出「开合 0.83」**（就在两腿中间，和角度标签同一套胶囊）—— 用户问「开合跳怎么没有角度」，
> 答案就是它不靠角度判；这个数字就是它真正的判据，跳到 0.66 以上就计次。
>
> **它是「限时计数」**（用户要求：固定 60 秒，看能跳多少次）—— 见下面那一节。

### 限时计数（开合跳 / 勾腿跳：固定 60 秒，看能做多少次）

用户要求「开合跳改为定时计次，比如固定 60 秒时长，看能跳多少次」，随后又要求
「勾腿跳也改为在固定时长内计次，比如 1 分钟勾腿跳，看看能跳多少个」。
做法是给动作库加一个字段 **`seconds`**（`catalog.js`）：**计数类动作**只要写了它，就变成**限时计数**。
**目前有两个动作用它**：**开合跳**（全身）与**勾腿跳**（下肢），都是固定 **60 秒**，时长都能在 🎯 里改。

- **计次规则一个字没改**：还是那几个关键帧一格一格走，走完一圈算一次
  （开合跳：并拢 → 跳开 → 收回；勾腿跳：站立 → **勾腿** → **勾另一条腿**），
  判据、分数、图标、进度条全都照旧。变的只是**什么时候算做完这一组**：
  从「做到目标次数」换成「**时间到**」（`isTimedReps()`，`catalog.js`）。
  > 勾腿跳的关键帧名字按用户要求就是「**勾腿**」和「**勾另一条腿**」（默认那套左右交替的通用说法是
  > 「发力 / 换边」，用在勾腿跳上很别扭）。分数仍然落在同样的格子上：**⑤ 站立 / 10 / 22 + 满轮 6**。
- **目标是时长，成绩是次数**：所以这两个动作有**两个单位** —— 目标用「秒」（`localizedExercise().targetUnit`），
  成绩用「次」（`.unit`）。🎯 运动设定里的目标预设也跟着换成 **30 / 45 / 60 / 90 / 120 秒**，
  「＋ / −」按 **15 秒**一步；**时长单独存在 `settings.seconds` 里**，不会和「次数」那个字段混在一起
  （这两个动作以前的目标分别是 50 次 / 20 次，同一个字段直接改成秒会出现「50 秒」这种莫名其妙的时长）。
- **画面**：大数字仍然是**次数**（做了多少个），下面那行是 `⏱ 剩余 42 / 60 秒`；进度环走**时间**进度。
- **语音**：剩余 **45 / 30 / 15 秒**各报一次「还剩 N 秒」，最后 **5 秒**单独喊「最后 5 秒，冲刺！」；
  次数照旧每 5 次报一次（`speakEvery: 5`）。**时间到**先喊「时间到，太棒了」，
  结算时播报「**60 秒完成 52 次**，+ 一句夸奖」（仍然不念分数）。
- **时间一到立刻停止计次**：庆祝动画那 2.6 秒里多做的几下**不算**进这一组的成绩
  （主循环给 `feedDetector()` 加了 `state.timeUp` 这道门），本组用时也停在 60.0 秒。
- **结算 / 记录**：结算面板里「有效次数 52 次 / 完成度 100%（按时间算）/ 本组用时 01:00」，
  说明写「⏱ 60 秒时间到：完成 52 次 · 本组得分 N 分」；🏆 最佳成绩和 📜 训练记录里都写成
  **「52 次 / 60 秒」**，换个时长练过也说得清。
- **达标只由时间决定**：普通计数动作的「做满目标次数就达成」和「做一半提醒」对限时计数不适用
  （60 次 ≠ 60 秒），有测试专门钉住这两条。
- **对新动作同样适用**：以后想让别的计数动作也变成限时，只要在 `catalog.js` 里给它加 `seconds: N`
  并把 `target` 改成同一个秒数即可，其余全自动。
- 想换成 30 秒、90 秒：在主页右上角打开 🎯 运动设定，选中这个动作后改时长即可（只对这个动作生效）。

> **勾腿跳怎么判**：站立原地左右交替，把脚跟往臀部勾。判据是**膝盖弯曲度**（勾起来那条腿的膝角），
> 三个关键帧 = **① 站立 → ② 勾腿（那条腿的膝角 ≤120°）→ ③ 换另一条腿也勾到 ≤120°（换边那一刻计一次）**，
> 画面上的图标也是**站立勾腿**的火柴人（第一格站直、第二格勾近侧腿、第三格勾远侧腿），
> 不是躺着的图 —— 用户反馈「图标应该是站立勾腿跳的图标」，因为分侧指标原来落到了通用分支、画成了躺姿。
>
> 最后一格用的是**识别器自己的「换边成功」标记**（`switched`），所以它点亮的那一刻就是计次那一刻；
> 「刚做完那条腿要先回到 ≥126°」只是补充条件，写在弹窗那一格的说明里，不再单独占一格。
>
> 也因为这个节奏（一秒能勾两下），它和开合跳一样**每 5 次才报一次数**（`speakEvery: 5`），不做逐次播报。
>
> #### 「慢慢跳能识别，正常速度 / 跳快一点就计不上」——交替判据太死（已修，四轮；快跳后来又补了第二路证据，见下）
>
> 用户先后反馈了三次：「慢慢跳可以识别，正常速度或快一点就无法计次」「跳得很快还是有点无法成功计数」
> 「整体好很多了，但依然有少数几次没计上」。用「真实管线」（合成姿势 → 平滑 → 指标 → 识别器）逐帧复现后，
> 一共查出 **4 个**原因，全都在**左右交替类动作的判据**上（勾腿跳 / 登山者 / 死虫式共用同一套引擎）：
>
> 1. **旧判据要求「另一条腿几乎伸直」**：一侧在做（膝角 ≤`onValue`）**且另一侧 ≥`offValue`**。
>    真人原地快跳时支撑腿的膝盖根本不会绷直（实测停在 **120°~140°**），旧 `offValue = 135°` 几乎永远不成立
>    → **一次都计不上**；慢慢跳时人会把腿伸直接地，才偶尔能过。
>    **现在只要求「另一侧没有同时在勾」**（真正的交替语义），支撑腿弯着也算「没在做」。
> 2. **「在做」的门槛太深**：快节奏 + 动作模糊 + 采样 + 平滑滤波会让**采样到的**最小膝角比真实值浅 10°~30°，
>    旧 `onValue = 100°` 经常够不到。**逐轮放宽到 126°**（`offValue = 132°`，只留 6° 迟滞带）。
>    边界（**宽松模式的取舍**，测试里分别钉住两侧）：原地小跑只下探到 ~150°、快跑抬腿到 ~133° → 不计次；
>    **明显抬膝（到 ~115°）就算**。
> 3. **很快的勾腿「一帧就完成」**，而旧的两条计次路径都要多等一帧：
>    「保持 `holdMs` 才计次」抓不到单帧尖峰；「回到休息位再结算」在快节奏下也漏 ——
>    勾完那条腿只回到 121°~126°，**迟滞状态会「粘住」**不放，后面的次数全丢。
>    **现在改成在「进入在做」的上升沿计次**（`countRises`）：只看这一帧有没有进到线内，和退出线无关。
> 4. **两条腿同一帧一起进线**（最后一轮才查出来）：快跳时人是在原地弹跳，**支撑腿也会跟着下沉**，
>    常常出现两条腿同帧跨过判定线；旧写法要求「恰好一侧进线」，这一帧就**整轮丢掉**。
>    现在改成：这种情况若**一侧明显更深**（差 ≥ `leadMin` = 18°，说明那条才是真勾起来的腿）就按它计次；
>    两条腿一样深（一起弯，不是交替）仍然不认。
>
> 另外保留两条保护：**迟滞状态**（进入 126° / 退出 132°，只用于画面上的深度条与 🐞 诊断，不参与计次）
> 与 **700ms 超时**（一侧连续「在做」超过 0.7 秒就判它做完，防止状态锁死）。
>
> 同一批修复也应用在**登山者**（进入 112° / 退出 124°）上。
> **死虫式**后来按用户要求整套判据重做（它的问题不是「太快」，而是判错了东西，见下面的专段）。
>
> **实测效果**（真实管线，1 个周期 = 左勾一次 + 右勾一次；勾到膝角 70°）：
> 每侧 700~300ms 一轮（一秒 1.4~6.7 下）在 30fps 下都计到 **103%~113%**；
> 支撑腿每步下沉 25°、勾得浅（膝角只到 100°）、很窄的尖峰（勾一下马上回来）都还是 **104%~106%**；
> 同样的窄尖峰在旧阈值下只有 61%。低帧率下仍在 500ms 一轮左右保持 104%，更快的会开始漏（见下）。
> **已知极限**（不是判定线的问题，是采样问题）：帧率降到 15fps 且单次勾腿特别短（<100ms）时，
> 采样可能整轮打不到峰上 —— 这时提高摄像头帧率/换更好的机器比调线更有效。
> 反例（**必须 0 次**）：原地小跑（膝角 150°）、快跑抬腿（133°）、两条腿同步一起弯（含一起弹跳）。
>
> `tests/test-detectors.mjs` 的 `[7c]` 段用**真实帧**把这件事钉住：五种节奏（1000~430ms 一轮）+ 15fps +
> 支撑腿没绷直 + 勾得浅 + 带噪声都要计到 ≥90%，两个反例必须一次都不计，并分别钉住 115° / 133° 两条边界；
> 这一轮又补了**支撑腿长期折在判定线以内**的三种快跳场景（折 60 / 70 / 80°，一轮 430~500ms）要计到
> ≥80%~95%，以及 `perSide.kick` 的量纲断言（腿伸直 >0.95、折 35° 仍 >0.95、折 120° 落到 0.5~0.72）；
> `tests/test-engines.mjs` 另外补了「只有一帧的尖峰（33ms 里勾完）也算一次」「同一条腿连着勾不刷次数」
>
> #### 「跳得时候经常无法计数，尤其是跳得快的时候」—— 再补第二路证据（脚跟到臀部）
>
> 上面四条把「上升沿 / 门槛 / 同帧跨线」都修过一遍了，但快跳时**仍然会漏**。这一轮用逐帧探针把
> 剩下的原因定位到两点：
>
> 1. **快跳时人是在原地小弹跳，两条腿都不会再伸直** —— 支撑腿的膝盖会长期停在判定线以内
>    （实测 120~140°），于是「这一侧不在做」这个状态再也不出现，**交替的上升沿就再也抓不到**，
>    后面的次数整段丢掉（探针：支撑腿折 70° 时旧判据只能计到 15/37 次）。
> 2. 只看膝角这条路，**没法把「支撑腿跟着弯」和「真的勾起来了」分开** —— 两者的膝角本来就近。
>
> 所以给勾腿跳补了一路**跨度大得多、而且是相对自己基线**的证据：
> **`perSide.kick` = 脚跟到同侧髋的距离 ÷ 腿长**（见 `src/metrics.js`），判定写成
> 「比自己『腿伸直』时近了 **0.12**（默认）就算勾起来」。实测这个量（同一条腿）：
>
> | 状态 | 膝角 | kick |
> |---|---|---|
> | 腿伸直（站姿基线） | 172° | **1.01** |
> | 原地小跑（折 35~40°） | 140~145° | **0.97~0.98** |
> | 明显抬膝（折 65°，旧的「浅勾」边界） | 115° | **0.88** |
> | 真正勾到臀部（折 120°） | 60° | **0.56** |
>
> 于是 **两路证据取「或」**，并且加了一条关键约束：**膝角那一路额外要求「脚跟至少也上来 0.06」**——
> 支撑腿的脚跟几乎不动（0.97~0.99），所以它再弯也不会被当成勾腿（这正是第 2 点的解法）。
> 第二路量不到时（脚跟可见度 < 0.4、或还没建立基线）自动退回膝角那一路，**绝不因为量不到就不计次**。
>
> 另外把「两条腿同帧跨线」从「当帧分不出就丢掉」改成**挂起 200ms**（`tiePair`）：等这一小会儿里
> 哪条腿先明显更深就算谁 —— 快跳时更深的那条常常要再一两帧才显出来。
> 判定用的是**同一路证据内部**的差值（kick 用 0.06 腿长、膝角用 18°），两条腿一起弯依旧一次都不计。
>
> **实测效果**（真实管线，1 周期 = 左勾 + 右勾，勾到膝角 70°，支撑腿也弯到线内）：
>
> | 场景 | 修之前 | 修之后 |
> |---|---|---|
> | 430ms 一轮、支撑腿折 70° | 15/37 | **37/37** |
> | 430ms 一轮、支撑腿折 80° | 5/37 | **36/37** |
> | 500ms 一轮、支撑腿折 60° | 28/32 | **31/32** |
> | 原地小跑（不该计次） | 0 | **0** |
> | 两条腿同相一起弯（不该计次） | 0 | **0** |
>
> 进度条第二格「勾腿」也改成用**识别器自己的判定结果**点亮（`anyKicked`，就是两路证据取「或」之后的结果）——
> 否则会出现「靠第二路计了次、而那一格还是灰的」，违反「所有关键帧都做完才计次」。
> 🐞 面板那一行现在同时显示「膝角/脚跟到髋」两个读数，并多一行「第二路证据」，
> 以及「两条腿同帧一起勾不计次」这一条也照旧保留。
>
> ⚠️ **建模踩过的坑（记在这里）**：测试里折小腿的动作最初写在**归一化坐标**里，
> 而画幅比例（16:9）会把角度放大近一倍 —— 所谓「支撑腿只折 35°」在真实几何里是 **126°**（深蹲级别），
> 于是模型比真人苛刻得多、还误导了阈值选择。现在折腿统一走
> `tests/synthetic-pose.mjs` 的 `foldShin()`（在**公制空间**里折叠，折 X° 就是膝角 180−X°）。
>
> **站姿门控用的是「不依赖地面线」的那一版**（`standUpright`）：只看「躯干倾角 ≤52°」+「肩高于髋 ≥0.5×躯干长」。
> 用户反馈「我明明站好了、躯干倾角只有几度，它却总说我没站好」—— 普通 `stand` 门控还要求
> 「膝离地 ≥0.28、髋离地 ≥0.55 倍躯干长」，这两个量都以**校准地面线**为基准，地面线一旦偏了
> （脚出画、校准时人没站到位）就会一直判不过；换成「肩高于髋」这种**身体自己跟自己比**的判据后，
> 站着 ≈ +1.0×躯干长、躺着 ≈ 0 都照旧分得清，但和地面线在哪完全无关。
>
> ⚠️ **这个门控踩过一个符号坑，记在这里免得再犯**：画面坐标 y 向下增长，所以「肩高于髋」这个量
> 用**正数**表达时是 `shoulderAboveHip = (髋.y − 肩.y)/躯干长`（站着 ≈ **+1.0**），
> 而原来那个「髋抬起」是它的相反数 `hipRise = (肩.y − 髋.y)/躯干长`（站着 ≈ **−1.0**，臀桥才用它）。
> 门控最初写成了 `hipRise ≥ 0.5` —— 等于要求「髋比肩高半条躯干」（几乎倒立），
> 于是站得再标准也永远过不了门控，画面上一直提示「**还没进入这个动作的姿势**」
> （用户报告的就是这个）。现在门控改用正数版 `shoulderAboveHip`，并且在
> `tests/test-detectors.mjs` 里加了**真实帧**（合成姿势 → `computeFrame`）的基线测试：
> 站着必须 `shoulderAboveHip ≈ +1.0`、`hipRise ≈ −1.0`，躺下必须被拦住 ——
> 以前那种「手搓帧」和代码犯同一个错，测试全绿也发现不了。
> 🐞 识别指标面板把两个量**都**列出来了（「髋抬起」/「肩高于髋」，互为相反数），
> 再遇到「说我没站好」直接看这两行就知道卡在哪。
>
> **它也是「限时计数」**（用户要求：1 分钟看能勾多少个）—— 固定 60 秒，时间到自动结算，
> 成绩就是这 60 秒里勾的次数；计次规则、关键帧、判据、分数都没动，细节见上面
> [限时计数](#限时计数开合跳--勾腿跳固定-60-秒看能做多少次)那一节。

### 音效与语音反馈

| 时机 | 反馈 |
|---|---|
| 达成一个要领 | **音阶上行的一声铃** + 画面飘出 `+12` 加分动画 |
| 整轮要领全过 | 三音上行「满分」和弦 + 加分飘字 |
| 每个要领第一次达成 | **语音念出该要领**，之后重复只响铃不念，避免刷屏 |
| 每跨过 50 分 | 上扬提示音 + **语音念一句激励语**（不报分数）+ 字幕显示「已经拿到 N 分！」 |
| 有效次数 +1 | 五声音阶计次音 + 语音报数 |
| 每 3 次（快节奏动作每 5 次） | **一句激励语**（24 句轮换：加油 / 太棒了 / 优秀 / 你太厉害了 …） |
| 整轮关键帧全做到 | 满分和弦 + 飘字 + 约 0.9 秒后补一句夸奖（完美 / 这一轮满分，太漂亮了 …） |
| 动作没算数 | 低频「噗」声 + 字幕指出问题 |
| 计时类保持中 | 每秒一声轻点 + 屏幕上分数持续上涨 |
| **计时类每满 5 秒** | **语音读秒「5 秒」「10 秒」…（平板支撑 / 体前屈都一样）**，屏幕上的秒数同时跳一下 |
| 达标 / 结束本组 | 庆祝和弦 + 达标飘字 + 结算面板（含得分与漏掉的要领）；语音只报「本组 N 次」+ 一句夸奖 |

音效与语音都可以在 ⚙️ 设置 弹窗里一键关闭。

> **计时类读秒**：平板支撑这类计时动作**每 5 秒播报一次当前秒数**（「5 秒」「10 秒」「15 秒」…），
> 用的是识别器自己累计的计时，所以：暂停（姿势垮掉）后继续接着数，不会从头念；换动作或重置计数后
> 从 5 秒重新开始；秒数一次跳过好几档（中途被打断很久）时只读当前这一档，不会连珠炮。
> 和「稳定保持 10 秒」这类要领语音撞在同一帧时，**读秒优先**（要领照样加分、打勾、响铃，只是不念那句话），
> 免得两句叠在一起听不清。语音关掉时不会出声，但画面上的秒数仍然会跳一下。

## 记录调试数据（排查「计不上」用）

> 用户要求：「请在我测试的时候记录下关节点和一些关键数据……在**运动设置**里面增加一个
> 『记录调试数据』的开关项，只要打开了，就把运动的关节数据按照一定的格式写在一个 log 文件里面，
> 这样下次你就可以分析真实的数据了。」
> 后来又说：「关于调试数据记录这部分，请**从运动设置放到全局配置**里面，还是维持 Ctrl+H 隐藏这样的模式，
> 正常情况下不显示。此外，**在视频状态下，按下 Ctrl+H 可以开启或者停止记录调试数据**。」

所以它现在在 **⚙️ 设置（全局配置）** 弹窗的最下面（不再是运动设定弹窗的内容），默认仍然**整组藏起来**。
两个 Ctrl+H 分工不同、互不冲突：

| 你在哪儿按 Ctrl+H | 会发生什么 |
|---|---|
| **⚙️ 设置（全局配置）弹窗里** | 把「🐞 调试数据记录」这一组**显示 / 收起**（默认藏着，弹窗不会因为它变长；刷新页面回到隐藏） |
| **视频画面状态下**（动作页、没开任何弹窗） | 直接**开始 / 停止记录**，不用打开弹窗 —— 提示条告诉你文件名（开始）或「共记了多少帧」（停止） |
| 其它地方（运动设定弹窗、动作主页…） | 不拦这个键，浏览器该干嘛干嘛（主页摄像头都没开，不会偷偷开始记录） |

> ⌨️ **Chrome 里 Ctrl+H 有时会被浏览器自己拿去开「历史记录」**（页面拦不住），
> 那就用 **Ctrl+Alt+H**（Ctrl+Shift+H 同样有效）—— 三个组合键的效果完全一样。
> 视频画面下按 Ctrl+H 时页面会主动 `preventDefault`，多数情况下能拦住浏览器的历史记录；
> 万一你的浏览器版本抢走了它，就改用 Ctrl+Alt+H（开始 / 停止的效果一样）。

- **「记录调试数据」开关**：打开后**每一帧**记一行，内容包括
  - 33 个关节点的**原始坐标**（含可见度）与**平滑后坐标**；
  - 这一帧算出来的**全部指标**（各关节角、髋 / 膝 / 肩离地高度、躯干倾角、身体直线角、命中偏差 …）；
  - **识别器内部状态**：阶段、进度、本轮峰值、它真正在用的判定线（`looseP` / `countElbow` / `backLine` …）、
    以及「上一次为什么没计上」（`reject`）；
  - **进度条点亮到第几格**（用来看「链走完了」和「计上」是不是同一帧）；
  - 事件行：每一次计次 / 半程 / 提示 / 要领得分，以及每一组的开始与结束（做了多少次、多少半程、用了多久）。
- **文件写在哪儿**：项目里的 `logs/pose-<动作>-<年月日-时分秒>.jsonl`（**JSONL**：一行一个 JSON）。
  页面把数据分批 POST 给本地预览服务器（`/__debug/log`，见 `preview-server.js`），由服务端**追加**写进文件 ——
  浏览器不允许网页直接写本地文件，所以走这条路。服务器没开时，还可以点 **「保存 / 下载文件」**
  把已经记下的内容作为 `.jsonl` 下载到浏览器的下载目录。
- **状态行**会说清楚：记录中 · 文件名 · 已记多少帧 · 多少 MB。
- **画面右下角会出现一个「正在记录」角标**（用户要求）：
  > 「一旦这个开关打开，则在视频屏幕的右下角要出现一个图标，显示其正在记录帧数据，
  > 同时用数字显示已经记录了多少帧了。」
  角标贴在**视频画面右下角**、全屏按钮的上方：一个**呼吸的红点**（一眼看出「在录」）+ **已记帧数** + 单位文案，
  鼠标移上去写着「正在记录调试数据（帧数实时更新）」。它**只提示、不吃鼠标事件**（`pointer-events: none`），
  不会挡住右下角的按钮；开关一关就立刻消失，所以「我到底还在不在记」不用再进弹窗确认。
  数字取的是 `poseLogger.status().frames`，也就是**真正写出去的行数**（不是循环帧号 ——
  队列满了会丢帧，屏幕上必须是实际记下来的数量）；主循环每 15 帧（约半秒）刷一次，
  既能看见它在跳，又不会每帧都去写 DOM。
- **体积**：一分钟几十兆（一帧约 1KB）。平时关着，只在排查时打开；测完把**文件名**告诉我，我直接读文件分析。
- ⚠️ `logs/` 已经写进 `.gitignore`：里面是**真实的关节数据**，只留在本地，不会进仓库。

## 站不进轮廓 / 没反应？排查四步

**① 先确认版本。** 页面标题旁应显示 `v3.0`。如果没看到，说明浏览器还在用缓存的旧版本 —— 按 **Ctrl + F5**（Mac 是 Cmd + Shift + R）强制刷新。

**② 先看右侧的「运动前校准」面板。** 哪一项没打勾，照着面板下方那句话做即可（**只有「识别到人体」和「全身入镜」两项会拦着开始**；躺姿动作的项目更少）：

| 面板提示 | 含义 |
|---|---|
| 没看清你的全身：请退后一点… | 模型没找到人或部位出画 |
| 离摄像头太远 / 太近：往前走一点 / 往后退一点 | 身体在画面里的大小不对 |
| 往右站一点 / 往左站一点，站到轮廓中间 | 左右没居中 |
| 往画面上方 / 下方站一点 | 上下位置不对 |
| 请正对摄像头 / 请侧对摄像头 | 机位与当前动作不匹配 |
| 很好，保持不动… | 只差最后一秒了 |

**③ 再看画面下方的状态条**，它会同步显示同一句话；开始训练后则显示「下一步该做什么、还差多少」。

**④ 打开 ⚙️ 设置 → 「🐞 识别指标」**（校准或训练中都可用）。画面下方会实时列出识别器看到的数字，例如：

```
视角 侧面✓(0.18) · 全身 ✓ · 双腿可见 ✓ · 躯干倾角 6° · 膝 176° · 肘 172° ·
髋 172° · 身体直线 175° · 髋抬起 -0.98 · 肩高于髋 0.98 · 大腿离水平 88° · 可见度 0.94 ·
虚线轮廓 ✗ · 状态 running
```

对照判断：

| 症状 | 原因 | 处理 |
|---|---|---|
| `视角 侧面✗(0.90)` | 机位和当前动作要求不一致（正面动作要正对、其余要侧对） | 按状态条提示转身：自重深蹲 / 相扑深蹲 / 深蹲跳 / 波比跳正对镜头，其余侧对 |
| `全身 ✗` | 有人体部位出画 | 退后 1~2 步，让头顶到脚都进画面 |
| `没检测到人体` | 太远/太近、逆光、背景与衣服同色 | 靠近一点、面对光源、换衣服、换分辨率更高的摄像头 |
| `躯干倾角` 长期 > 32° | 摄像头是斜的或人站歪了 | 摆正摄像头（或用书本垫平） |
| 勾腿跳一直说「还没进入这个动作的姿势」 | 站姿门控看的是「肩高于髋」 | 看面板的 **`肩高于髋`**：站着应该是 **≈ +1.0**（同时 `髋抬起 ≈ −1.0`）。如果它接近 0 或负数，说明人确实躺/坐着（或躯干折过去了）；这两行都正常却还进不去判定，就是 bug，把这一行念给我 |
| 数字正常但没打勾 | 卡在某一步的阈值上 | 状态条会直接写出还差多少（如「现在已经蹲到 62%（100% = 大腿水平）」） |
| `虚线轮廓 ✓` 而 `状态 running` | 不该出现（识别成功后轮廓必须收起来） | 记下这一行的状态与动作名反馈 —— 训练三态有硬性不变量与逐帧测试守着，真出现就是新 bug |

## 常见问题

**Q：端口 4174 被占用怎么办？**
换端口启动即可：`PORT=8080 node preview-server.js`（Windows 用 `$env:PORT=8080; node preview-server.js`）。
查占用：macOS/Linux 用 `lsof -i :4174`；Windows 用 `netstat -ano | findstr 4174`。

**Q：浏览器说"相机不可用 / NotAllowedError"？**
按上面「摄像头权限设置」把系统和浏览器两层的权限都打开，然后**完全退出浏览器再重开**。

**Q：页面提示"姿态模型加载失败"？**
多半是 `.wasm` 的 MIME 不对。用自带的 `node preview-server.js` 最稳；用 Python 需要 3.9+。
另外确认 `vendor/` 目录完整（从 GitHub 下载 ZIP 时最容易漏解压整个目录）。

**Q：画面卡顿 / 帧率低？**
在 ⚙️ 设置 里把「模型」切到 **轻量**、关掉「📐 角度」；换一台性能更好的设备。识别在 10~15 FPS 下依然可用。

**Q：手机能用吗？**
可以。手机浏览器打开同一个地址即可（手机与电脑需在同一局域网，且服务器要监听 `0.0.0.0`：
把 `preview-server.js` 里的 `'127.0.0.1'` 改成 `'0.0.0.0'` 后重启）。注意这样同一网络里的其他人也能访问。

**Q：数据存在哪里？**
训练记录与最佳成绩存在浏览器的 localStorage 里，换浏览器或清缓存会丢，不会上传到任何服务器。

## 想加动作 / 调分值 / 改阈值

**加一个动作只要在动作库里加一条配置**（不用写识别代码）：

1. 在 `src/catalog.js` 的 `EXERCISES` 里加一条，例如
   `e('myMove', '🔧', ['core'], { plan: 'repSupine', posture: 'supine', judge: 'clear', target: 15, params: bend({ metric: 'kneeClear', gate: 'supineLow', up: 0.15, down: 0.85 }) })`；
2. 在两份 `src/locales/*.js` 的 `ex` 里补上 `myMove: { name, cameraHint, goal }`
   （要领与注意事项会自动套用所属「族」的模板，想单独写就加 `howto` / `tips`）；
3. 跑 `npm test` —— 测试会检查五类清单、中英两种语言的文案、每个动作的识别器与计分方案是否齐全。

- **改分值或要领文案**：编辑 `src/steps.js`（结构与分值）与 `src/locales/*.js`（文案）。
  每个步骤就是一个 `{ id, labelKey, points, check, hint }`；`check(frame, det)` 返回 `true` 即表示这一步达成。
- **改判定阈值**：
  - **通用引擎动作**（库里绝大多数）：改 `src/catalog.js` 里该动作的 `params` ——
    `metric` 用哪个量（`kneeBent` / `elbow` / `hipRise` / `kneeClear` / `shoulderClear` …）、
    `gate` 要求什么姿势（`stand` / `prone` / `supine` / `seated` / `sideLying` …）、
    `up` 起始值、`down` 到位值、`looseP` 宽松计数线、`minRepMs` 最快用时、`flight` 是否要求离地；
  - **手写识别器**（俯卧撑已改回通用引擎）：改 `src/exercises.js` 里对应常量（都有中文注释）——
    `SQUAT_FRONT`（在 `src/steps.js`）：`standRatio` 0.86 / `enterRatio` 0.78 / `bottomRatio` 0.40 /
    `looseRatio` 0.62，单位是「髋比膝高多少 ÷ 小腿长」，站直 ≈ 1.0；
    `LUNGE`：`enterKnee` 146 / `looseKnee` 142 / `downKnee` 128 三档膝角，`backKneeDrop` 0.66，
    `enterHoldMs` / `exitHoldMs` 是抖动宽容时间；
    **俯卧撑**已经不再手写识别器了（用户要求「大幅度简化计次标准」）：它就是通用引擎 +
    `catalog.js` 里那几行 `params`（`up` 170 / `down` 95 / `enterP` 0.15 / `looseP` 0.30 /
    `bottomP` 0.75 / `ignoreP` 0.20 / `backP` 0.12 / `minRepMs` 350），只判肘角；
    `BRIDGE.upRise` 0.22、`liftAngle` 150、`topAngle` 165（顶起 / 到顶的髋角副判据）、`minRepMs` 420；
    `PLANK.bodyStraight` 142；
  - `HoldDetector.graceMs`：计时类动作的容错宽限期（默认 1200ms）。
  - **「这一帧算不算识别到人」的门槛**（`src/metrics.js` 顶部，用户反馈放宽过）：
    `PERSON_VIS_MEAN` 0.10（核心关节平均可见度）、`PERSON_VIS_MIN` 0.02 与 `PERSON_VIS_SLACK` 2
    （判定用的 15 个点里允许两个看不见，第三个起才要求 ≥ 0.02）、`PERSON_MIN_TORSO` 0.02
    （躯干长不得小于画面高的 2%，挡掉关键点塌成一点的退化帧）。`src/calibration.js` 读的是同一个 `PERSON_VIS_MEAN`。
  - **只有宽松一档**：`DetectorBase` 里已经没有 `strict` 开关了（大体做到就计次数，动作不标准只用语音纠正 +
    分数打折）；计次判据只有一条 —— 进度条上的关键帧链全部点亮。

改完请跑 `npm test`，测试里已经写好了这些动作的标准幅度，能立刻告诉你是不是调过头了。

**识别原理**：所有判据只用**角度**和**除以躯干长的比例**，与身高、机位距离无关；
关键点先按画面宽高比校正再算角度，并用 One Euro 滤波抑制抖动，所以同一套阈值适配不同的人和机位。

## 隐私与许可

- 画面只在本机浏览器里处理，**没有任何上传**；模型与 wasm 都是本地文件，断网可用。
- 服务器默认只监听 `127.0.0.1`，同一网络的其他人无法访问。
- 训练记录只存在你自己的浏览器 localStorage 里。
- 第三方资源：`vendor/` 下的 MediaPipe Tasks Vision（wasm）与 Pose Landmarker 模型来自 Google MediaPipe，遵循 **Apache License 2.0**。
